# 可认证的当日联合博弈求解器设计（2026-10-16）

本文是算法设计，未实现新求解器、依赖或默认策略。依据当前代码和FS01联合漏攻复查，目标是用无损压缩、按需收益计算和可验证的最优回应，替代“有限探测未发现失败即视作安全”。

## 1. 精确性的范围

可以精确求一个有限、完整定义的局部博弈。需要同时明确：

- 行动域：当前黑方靶位已经公开，穷举其全部合法牌面及红方全部合法三牌；不声称已优化黑方先前选择靶位的策略。
- 世界域：已知完整剧本，或给定有限身份／当事人分布。只用4个粒子时，结论仅针对该4粒子模型；完整角色支持不代表当事人联合支持也完整。
- 后续选择：日末前全部合法能力、顺序、拒绝及事件目标，或者明确冻结的续演政策。有限定式路线不构成全部能力策略的证明。
- 收益：当日存活0/1，或明确指定的日末估值。日末估值的最优行动不自动等于整局获胜概率的最优行动。

第一落点建议为**已知剧本、未知本日黑牌、双方能力精确搜索、当日存活收益**。揭牌后身份双方已知，可按当前引擎的合法决策树进行确定性的min/max与转置缓存。公平版若冻结合法红方续演政策，也能精确解该政策限制下的根出牌博弈；它不包含所有信息能力决策的全局优化。

公平版同时优化揭牌后的能力时，不可在各世界独立给红方选最优技能：同一红方信息集必须共用决策。可使用保留perfect recall的信息集展开和sequence form；两人零和有限树可写为相对显式树规模线性的LP，但树本身仍可能很大。[von Stengel讲义](https://conferences.mpi-inf.mpg.de/adfocs-24/material/Bernhard/2ext-adfocs.pdf)

不承诺所有剧本、整轮／整局均可在秒级精确求解。每次返回值须附世界、行动、后续决策、收益及数值误差的范围说明。

## 2. 黑方提交顺序与混合策略

当前公开根上黑牌已经暗置；红方随后提交三牌，之后才揭牌。黑方选择牌面时可以知道红方的策略分布，不能知道其尚未实现的私有随机抽样；揭牌后，黑方能力可以合法响应已揭示红牌。

固定已知世界时，令`A[r,b]`为完整红牌r与黑牌b在上述后续模型下的收益。最优纯策略为`max_r min_b A[r,b]`；混合策略求`max_x min_b Σ_r x[r] A[r,b]`。

若每次先抽中红牌r，再为该r选择黑牌b并平均，算出的是`Σ_r x[r] min_b A[r,b]`。这给黑方增加了看到红方本次随机结果后换牌的权限，会低估混合策略。例如匹配收益矩阵`[[1,0],[0,1]]`，纯策略保证0，双方均匀混合的值为1/2，错误顺序仍返回0。

黑方本日牌面与揭牌后的能力回应需要分开建模，不能放在同一条“看到红方三牌后任意重选”的攻击路径中。

## 3. 可做的无损压缩

### 3.1 局部结算传递表

预计算每个目标、红牌／空、黑牌／空、全局结算标志对应的局部效果程序，整套三牌由少量查表组成。

- 移动方向先去重，再按方向组合；两张同向只移动一次，禁止移动和最终禁入判断保留。
- 正负计数及截断按真实结算顺序执行；仅保存最终数值可能漏掉途中触发。
- 全局禁止密谋数量、病毒计数触发、侍从跟随、行动复写等非局部依赖另有显式节点。不能把各目标结算完全独立化。
- 现有`CardProjectionModel`可复用数据布局，但其邪教徒保守覆盖、侍从不确定跟随等近似不能直接用作精确结算或安全证明。先定义支持能力集合；不支持时回退真实引擎。

### 3.2 按结算结果缓存，保留信息分支

最有价值的复用单位是多套牌到达的相同规则状态，而不必强求它们成为同一个博弈动作。

建议分两种key：

1. `RuleStateKey`：规则／剧本版本、当前与初始身份、角色位置与存活、全部计数、阶段／日／轮、每席手牌与限次消耗、已用能力、保护、跟随／区域状态、待决选择／同时触发快照及一切被规则读取的历史摘要。
2. `InformationKey`：双方授权观察、已知私密答案及使后续策略充分确定的信念／历史状态。无法证明摘要充分时保留完整相关观察历史。单独的边际矩阵不足以表示析取和跨维关联。

相同规则状态可以共用规则转移结果。若公开揭牌或知识不同，继续保留不同信息节点。固定续演政策如果根据牌面／事件构造随机种子，其seed也是该政策评价的输入；省略它会改变当前固定政策结果。

公平续演还需单独审计随机性的来源：现有`OracleProtagonistAgent._policy_state_key`读取`world.view("m")`，部分续演随机种子使用该key。红方的可观察输入相同，不保证按私有世界生成的单次随机续演也对应同一信息集策略。新的公平精确后续策略必须按授权信息集定义；保持旧随机轨迹等价和证明公平策略合法性是两项不同验收，不在本次设计中认定已完成。

`Game.state_key(viewer)`删除events且基于观察视图，不可直接充当完整私有规则／信念状态的转置键。先逐字段审计规则读取与阶段状态，再定义独立key。

### 3.3 行为等价类和支配

可合并行动的强条件是：对全部可行对手行动和世界，产生等价收益及后续规则／信息状态；可在指定horizon内证明更弱的等价，但须标记范围。

- 地点上的非密谋黑牌可以按本次效果压缩，保留实体成员。斜移等限次牌的消耗、未来手牌及公开揭牌不同，不能直接合并成整局等价策略。
- 相同普通牌由不同红方席位打出，只有完整资源／知识／轮换结构存在相应对称时才能消除席位置换。限次牌所有者必须保留。
- 当前共同样本／部分列上的相同收益，不足以合并整行或整列；可以暂合并并在新反例出现时拆分。
- 纯支配删除需要覆盖全部对手行动及世界。只在若干攻击上更好属于排序启发，精确求解时不作为硬剪枝。

**当前`JointActionSpace`包含AI策略限制和shortlist等价，不是全部合法行动域的精确性证书。** 例如禁止密谋最多一张、选择无效填充代表、保留部分普通牌的方式，都须在精确收益范围内证明支配／等价，或在完整档恢复全部合法动作。47904是近期根的当前剪枝域大小，不能写成全部合法动作数。

## 4. 核心：按需矩阵与Double Oracle

维护小型策略集R0、B0及已计算的收益缓存：

1. 在当前小矩阵上解零和LP，得到红方分布x、黑方分布y。
2. 红方回应器：在**完整红方行动域**中寻找对y收益最高的完整三牌。
3. 黑方回应器：在**完整黑方行动域**中寻找对x收益最低的整套牌面。
4. 添加尚未包含的最优回应，只补新增行／列实际需要的收益，复用状态缓存。
5. 用全域最优回应算下界L、上界U；`U-L≤epsilon`才给出对应epsilon的认证。

固定世界时：`L=min_b Σ_r x[r]A[r,b]`，`U=max_r Σ_b y[b]A[r,b]`。

精确最优回应与精确收益下，有限策略博弈最终收敛；最坏情况仍可能展开整个行动空间。已有工作给出了这一方法；本项目的效果编译、阶段缓存和信息约束需要另行实现／验证。[McMahan、Gordon、Blum，ICML 2003](https://www.cs.cmu.edu/~avrim/Papers/mgb.pdf)

当前启发式可用于初始化R0／B0、安排攻击检查顺序，不能替代全域分离检查后仍声称最优。允许预算耗尽返回当前策略，但保留尚未闭合的上下界和未完成维度。

## 5. 多世界公平版本：避免黑方策略笛卡尔积

令h为角色／当事人类型，p[h]为给定后验，黑方知道h，红方根行动共用x。若后续政策已经固定或能被正确的信息集模型概括为`A_h`，则：

`V = max_x Σ_h p[h] min_b Σ_r x[r] A_h[r,b]`。

对应LP：

```text
maximize  Σ_h p[h] v[h]
subject to
    Σ_r x[r] A_h[r,b] >= v[h]   对每个h和每个合法b
    Σ_r x[r] = 1
    x[r] >= 0
```

黑方可以针对不同h选择不同牌面，因此黑方回应器按h分别最小化，返回y[h]。不必显式构造`B^H`套“每种身份各选一套牌”的完整策略；约束按h分块，固定x的黑方回应复杂度是各类型行动数之和。

红方回应器则最大化`Σ_h p[h] Σ_b y[h,b] A_h[r,b]`，只能返回同一个r；禁止在每个h独立给红方选牌再平均。

全域上下界为：

```text
L = Σ_h p[h] min_b Σ_r x[r] A_h[r,b]
U = max_r Σ_h p[h] Σ_b y[h,b] A_h[r,b]
```

这是固定有限世界／收益模型内的保证。4套完整身份与30套合法当事人可能有120种类型，不能把4次角色／当事人联合抽样称为完整120类型。仅当未来当事人不影响本日规则、任何可用查询／信息决策及日末收益时，才可边缘化其维度并累加质量。

## 6. 最优回应器与性能

### 6.1 先找保证存活，再求最高保障率

当目标仅为0/1当日存活时，可先尝试找到对全部类型／黑牌都安全的红牌。使用反例约束生成：提出完整红牌、全域找攻击反例、加入已证实的失败约束，再求候选。若找到并完成全域认证，纯策略价值已为1，无须解混合。

若不存在纯策略全安全，继续求纯maximin或混合策略。某个小概率世界要求的防守不应无条件变成全部策略的硬约束，否则可能删掉最优期望策略。

### 6.2 真正的无损剪枝

对未知收益先用合法范围`[0,1]`，再由引擎或已证明的规则条件收紧。部分求和形成最优回应的上下界；不能超过当前最好完整结果的分支即可停止。

- 红方最优回应只需面对y的非零支持；黑方最优回应只需面对x的非零支持。
- 已知失败反例优先，复用相同物理状态；共享强制结算前缀、阶段DAG和能力子树。
- 轻量评分只排序；未经证明的“风险0／风险大于0”均不能直接填写精确收益。
- 动态状态应使用紧凑整型数组／bitset，查表批处理；验证后再考虑编译扩展。编译或向量化本身不能消除错误的等价假设。

### 6.3 规模与成本判断

以近期剪枝域47904红牌、504黑牌、4世界为示例，全矩阵约9657万对。二值收益bitset约11.5MiB，float32约368.4MiB；内存通常比逐对完整结算容易解决。

若当前支持仅8套红牌、每世界4套黑牌，一轮全域最优回应候选收益请求约`4×(504×8+47904×4)=782592`，可以只按需计算并缓存。它是请求数量示例，不是实测速度，也不是最坏复杂度保证；全合法域及更多世界会增加成本。

固定政策、真实引擎毫秒级单对评价仍可能很慢。优先统计“不同规则状态数、规则缓存命中、不同信息状态数、能力子树数、精确引擎调用数”，不只统计候选／粒子个数。

## 7. 数值认证和实现顺序

普通浮点LP给epsilon近似。严格最优需要有理数重建／求解后，以全域约束及原始精确收益复核原始／对偶可行性和等值；无法完成时明确报告误差，不能以显示小数相同代替证明。

建议分阶段：

1. **精确已知世界基准**：恢复／证明完整合法三牌域，单个FS根，真实引擎完整能力树，状态缓存，直接穷举小局面作裁判；输出最优纯策略及“当前局面是否存在保证存活方案”。
2. **压缩验收**：局部效果程序、规则／信息双key、资源保留、观察边保留；逐组合与引擎对照，独立反例查找。当前边缘遗漏根作必测回归。
3. **混合策略与Double Oracle**：小矩阵LP、完整最优回应、L/U/gap；匹配型博弈应得到纯保障0、混合保障1/2。先保留直接全矩阵裁判路径。
4. **公平固定后续版本**：共同红方行动、按世界分块黑方回应、原后验质量；区分完整类型与采样近似，禁止世界间红方策略融合。
5. **公平信息能力与跨日**：sequence form／信息集最优回应和必要历史；与当前固定政策基线分开验收。整局扩展、三／四人独立红方另做设计。

开发需新增可选LP依赖；当前系统Python未安装SciPy／NumPy，不在本次设计阶段安装。主程序、GUI和现有AI入口保持不变。

建议证书字段：`action_domain_complete`、`belief_domain_complete`、`continuation_mode`、`horizon`、`utility_version`、`compression_version`、`ruleset/scenario_digest`、`best_response_complete`、`lower_bound`、`upper_bound`、`numeric_error_bound`、`stop_reason`。

只有覆盖和数值条件均满足的返回值才标记认证最优／epsilon最优；超时、启发式分离、有限路线或采样世界均显式标明范围。
