# MCTS 性能诊断与后续优化计划

本文记录 C2 朴素完全信息 MCTS 的性能基线和候选优化。`mcts_mastermind` 保持完整合法行动空间、UCT 与随机 rollout，
作为长期可选基线；`optimized_mcts_mastermind` 独立实现已验证的首批优化，二者均可从大厅和 benchmark 选择。

## 2026-09-16 基线

测试环境为当前 Windows/Python 3.14 开发机，使用 BTX 教学局初始状态：

| 树节点 | rollout 深度 | 用时 | 迭代率 |
| ---: | ---: | ---: | ---: |
| 32 | 12 | 0.321 秒 | 96.5 次/秒 |
| 64 | 24 | 1.693 秒 | 37.2 次/秒 |

首批优化完成后，在同一开发机、同一 BTX 分支局面与固定种子下重新比较：

| 模式 | 树节点 | rollout 深度 | 用时 | 迭代率 |
| --- | ---: | ---: | ---: | ---: |
| 朴素基线 | 32 | 12 | 0.332 秒 | 93.5 次/秒 |
| 优化 MCTS | 32 | 12 | 0.089 秒 | 347.5 次/秒 |
| 朴素基线 | 64 | 24 | 1.712 秒 | 36.8 次/秒 |
| 优化 MCTS | 64 | 24 | 0.344 秒 | 183.3 次/秒 |

以上是吞吐基准而非棋力结论；渐进拓宽改变固定小预算下的访问分配，因此后续仍需用固定剧本胜率评估策略强度。

`cProfile` 的 32 节点/深度 12 样本执行了 403 次状态转移、生成约 14,500 个 `ActionOffer`。累计耗时显示：

- rollout 占搜索时间约 92%；节点本身的 UCT 计算不是瓶颈；
- `deepcopy` 占约 77%，主要因为每次 `transition` 都复制完整游戏对象，包括不断增长的日志、决定记录和诊断 Trace；
- 合法行动转为类型化 `ActionOffer` 占约 25%，其中规范化 JSON 与 SHA-256 行动 ID 约占 14%；
- 初始出牌阶段分支很宽，平均每次合法行动枚举产生约 36 个候选；节点数和深度同时翻倍时，用时明显超过线性增长；
- 完整自对弈会在每个剧作家决策点重新建树，因此单次几百毫秒会累积为整局数十秒。

搜索曾在“整棵树小于节点预算”时重复 rollout 而不增加节点。C2 已加入穷尽节点向上传播和 `tree_exhausted`
停止原因；这是终止条件修复，不是行动剪枝。

- [x] 对八个规则集建立首个分支局面的统一基准，记录相同种子下的分支数、耗时、迭代数、所选行动与峰值内存；
- [ ] 为能力顺序、事件选择和最终猜测增加固定中后期状态，并保存跨版本结果；
- [ ] 在固定剧本自对弈中比较相同墙钟预算下的胜率；
- [ ] 将大厅短预算与离线强度预算分开，建立不会阻塞 SSE/房间锁的延迟目标；
- [ ] 记录“每个实际决策重新建树”造成的额外成本，作为树复用前的基线。

## P1：不改变搜索空间的工程优化（进行中）

- [x] 增加轻量搜索副本：不复制历史 replay、旧公开日志和已完成的因果 Trace，只保留规则结算需要的当前状态；
- [x] 为搜索内部提供原始命令转移，避免每个模拟候选重复生成显示标签与 SHA-256；网络行动 ID 仍保持现状；
- [x] 只有一个合法行动时直接推进，并在 Trace 中记录 forced transition；
- [x] 实际落子后保留仍匹配的子树，后续状态吻合时复用访问统计和后继分支；不吻合即丢弃；
- [ ] 评估可逆原地 `apply/undo` 或结构共享状态；只有所有规则集通过状态等价测试后才可替代 `deepcopy`。

## P2：候选剪枝与选择策略（进行中）

1. **渐进拓宽（已实现）**：宽分支节点只随访问次数逐步开放更多行动，避免 24 个节点平均撒在数十至数百个暗牌组合上；
   行动不会永久删除，预算增加后仍会逐步开放。
2. **行动先验排序（首版已实现）**：按立即胜负、击杀、关键人物/杀手阴谋和事件犯人不安等信号排列拓宽顺序；
   同优先级先以固定种子洗牌，先验不改变合法行动集合。
3. **支配与等价行动合并**：对完整后继状态键相同的行动只保留一个代表；对“必然无效果”的放置仅在能证明对隐藏信息、牌序、
   次数限制和日志均无差异时合并。
4. **战术终局求解**：立即获胜、立即失败以及强制结算链用 solver 标记；已证明的胜负节点不再 rollout，但仍保留可审计证明路径。
5. **分阶段宏行动**：把同一方连续的三张剧作家暗牌或多个可选能力顺序作为宏动作搜索，内部仍用规则引擎逐步验证；
   需要特别处理同目标禁放、手牌消耗和中途信息变化。
6. **动态 rollout 截止**：在轮回边界、事件结算后等稳定时间点评价；对低信息价值的强制流程缩短深度，对接近终局的分支加深。
7. **对手行动抽象**：主人公的明显等价反应可分组采样，但不能把主人公可见信息以外的“最优答案”硬编码进策略。
8. **置换表**：用完整状态键共享访问和值；进入 C3 后必须改用信息集键，不能把不同隐藏世界错误合并。

## P3：剧本条件化估值（待实现，棋力优先项）

深度 12 的 rollout 通常不能穿过完整的 3 天/3 轮，因此截断叶节点的估值比继续增加少量节点更影响行动质量。估值器应
从“所有剧本共用的若干计数物线性加权”改为由剧本 setup 编译：

1. **失败路线图**：从规则 X/Y、身份和事件建立关键人物死亡、事件触发、规则特殊失败、亲友死亡、时间旅行者等路线，
   每条路线包含阈值、所需前置条件、最晚日期和可用行动窗口。
2. **距离而非原始计数**：评价“离触发还差几次有效行动”和“截止前还剩几个行动窗口”，而不是把密谋、不安、友好直接
   线性相加；跨过阈值前后的分数必须体现规则悬崖。
3. **路线组合**：替代路线采用近似 `max` / 概率并集，互相依赖的路线显式建边，避免同一角色上的密谋同时被多项特征重复奖励。
4. **防守与反制**：计入主人公可用手牌、好感能力、移动限制、保护效果、公开知识及下一时间点可执行的反制，而不只看剧作家进度。
5. **阶段稳定性**：优先在行动结算后、事件结算后、日终等稳定边界评价；中间状态附带待结算效果，不能与稳定状态直接比较。
6. **信息集聚合**：完全信息搜索评价一个 setup；ISMCTS 对每个合法粒子调用相同估值器，再按信念权重计算期望值及可选风险项。

验收不以“看起来合理”为准：保存一批人工构造的近终局局面，验证终局 `±1`、关键阈值单调性和特例方向；再用更深搜索/
完整终局的回报作为标签，比较排序相关性、胜率校准误差和各特征组消融结果。现有 `MastermindEvaluator` 与朴素 MCTS 继续保留
为对照，不在新估值器通过这些测试前替换。

实施进度：FS/BTX 第一版已完成并只接入优化 MCTS；朴素模式不变。13 个已录入剧本均通过从初始状态到真实终局的
确定种子合法行动漫步，并在每个状态检查估值范围和数值有效性；规则阈值与方向性另有独立测试。下一步是保存中后期
固定局面，用更深搜索/完整终局回报校准组合方式和权重，而不是继续凭直觉调整常数。

## 验收护栏

- 每项剪枝必须可关闭，并与当前 `unpruned` 朴素模式在固定种子下对照；
- Trace 记录原候选数、保留数和每种剪枝理由，但这些资料只存在进程内调试边界；
- 根节点最终返回的行动必须仍属于后端当时提供的 `ActionOffer`；
- 八规则集状态等价、信息边界、终止性和立即胜负测试必须全部通过；
- 优化以单位时间胜率和决策延迟评估，不能只比较每秒节点数。
