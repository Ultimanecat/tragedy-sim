# 公平多世界博弈：分块求解与授权续演（T0.4，进行中）

本页记录T0.4有限世界内核的初期实现与校准。当前已有分块精确LP、Double Oracle、原质量及真实FS固定观察政策；后续 [公开联合后验桥](public-posterior-day.md)已接入矩阵／witness管线。完整隐藏历史支持、信息集能力优化仍待完成，默认AI和大厅入口保持不变。

## 1. 共同红方策略与分块黑方回应

每个世界h提供自己的收益矩阵`A_h`和原概率质量`p_h`。红方统一使用x，黑方按其已知世界分别回应：

```text
maximize_x sum_h p_h min_b sum_r x[r] A_h[r,b]
```

同一个x在所有世界使用，世界内不能分别优化红方行动再平均。黑方的本日暗牌也不能在看到红方本次私有随机抽样后重选；揭牌后的能力才按规则响应实际红牌。

受限博弈按世界保留少量黑方列。精确LP加shift使收益B全正后，求：

```text
maximize t
sum_h,b p_h B_h[r,b] z[h,b] <= 1       每个共同红方行r
sum_b z[h,b] = t                       每个世界h
z >= 0, t >= 0
```

每个等式用两条零右端不等式表示，初始松弛基可行，使用有理数Bland单纯形；零右端的退化情况同样受防循环规则约束。黑方条件分布为`z[h,:]/t`，红方分布由前R条约束的对偶价格除以t得到，值为`1/t-shift`。原始／对偶目标与原收益块的鞍点约束全部独立复核。

规模为`R+2H`条约束、`1+sum(C_h)`个变量，无须枚举`product(C_h)`套黑方条件策略。新增通用可行松弛基LP组件供T0.3与T0.4共享，没有新增依赖。只覆盖当前受限矩阵的LP解仍需完整域回应核验。

## 2. 按需收益与完整域回应

`BayesianDoubleOracle`维护共同红方行和每世界各自的黑方列、精确收益LRU缓存；逐世界独立找黑方最优回应，红方对所有世界条件策略的加权支持找同一个最优回应。完整黑方检查成本按各世界域规模求和，未物理展开条件策略笛卡尔积。

新增黑方列与本世界当前列下的收益底线比较，不能直接与全世界平均值比较；不同世界的局部收益本就可以不同。未知单元格不缓存为0，预算中断和部分求和遵循T0.3的可靠区间约束。历史最强L及对应x、历史最强U及对应条件策略分别保存，允许同一不可变模型续跑。

## 3. 原后验质量与遗漏质量

输入质量必须为正，允许总质量`m<=1`。所有全域界使用原`p_h`，遗漏的`1-m`按声明的收益范围补入区间：

```text
L = covered_L + (1-m)*utility_min
U = covered_U + (1-m)*utility_max
```

受限LP内部为缩放数值使用`p_h/m`，结果、最优回应加权和证书都恢复原质量；不会丢弃未纳入世界后直接宣称胜率更高。测试中覆盖0.9质量的全安全世界只能给[0.9,1]，仍保留0.1未知。

采样粒子总权重为1也不证明完整后验覆盖。`belief_domain_complete`须由上游明确声明；世界输入来自调用者，当前工具不能自动证明它就是真实完整后验。CLI的`--complete-posterior`是调用者断言，报告单独记录该来源。未核实的经验分布只支持该有限模型的结论，不能认证原后验或真实剧本胜率。

## 4. 固定授权续演

`FixedPolicyDayGame`采用固定红方政策，黑方仍搜索全部合法日末能力。政策只收到不可变`InformationState`，内容为：

- 团队授权视图，含公开事件历史、合法私密答案及三席手牌。
- 红方自己的命令记录，保留自己的能力选择记忆。
- 当前红方合法命令菜单。

输入没有私有`Game`、真实世界标签、隐藏身份、私密能力使用标志或隐藏黑方命令数量。不同世界的根必须有相同授权信息和同一版本的完整红方行动域，否则拒绝组合。

当前政策`PublicSkipOptionalPolicy`优先跳过可选能力，其余选规范顺序首项，作为简单、确定性的公平续演基准，棋力有限。自定义政策须为纯函数并冻结版本；求解期间检测版本变化。未来可以冻结更强的观察政策，或单独求信息集能力策略。当前固定政策模型的最优值不代表全部合法红方能力策略的最优值。

固定观察政策的值缓存同时包含完整规则状态、政策版本和授权历史输入，不能沿用仅按物理状态缓存的开眼最优值。旧`information_key`中的保守历史区分可用于内部缓存审计；政策输入不使用隐蔽命令占位符／决策序号作为信息，以免将看不到的操作数量变成选招依据。

## 5. 验证范围与入口

- 共同红方行动的反例：两个世界各自开眼能得1，合法共同策略只能得1/2。
- 条件黑方行动的反例：限制黑方共用一张牌会错误得到1/2，按世界分别回应实际值为0。
- 固定seed0–9、30个小型分块博弈，与显式枚举全部黑方条件策略的完整矩阵解一致；另核验原块约束。
- 12世界×2黑牌：分块LP为26约束／25变量，最后黑方回应最多检查24个候选，无须4096套条件策略。
- 预算、恢复、遗漏质量、带负值的效用范围、不完整覆盖和非法域有回归。
- 真实FS受控小局面的原生、缓存、编译结果与独立原生递归对照；私密角色／牌面／使用标志／隐藏命令数量不改变政策输入，公开历史与自己的选择会保留。

本阶段完整回归1018项通过（294.953秒，`references/exact-day-bayesian-regression-20261017.txt`）。共享LP重构同时跑过旧单世界混合策略、纯策略及缓存回归。完整回归和原生策略审计并发，耗时不作性能校准。

代码入口：`day_game/bayesian_matrix.py`、`bayesian.py`、`fair_engine.py`；T0.3的有理数LP与最优回应组件继续共用。

```powershell
python -X utf8 -m benchmarks.ai_bayesian_day --worlds references/worlds.json --time-ms 10000 --output references/bayesian-day.json
python -X utf8 -m unittest tests.test_day_game_bayesian_matrix tests.test_day_game_bayesian tests.test_day_game_fair_engine tests.test_ai_bayesian_day
```

`worlds.json`为数组，各项包含`label`、原质量`mass`（如`"1/10"`）、完整假设剧本`scenario`和恢复出牌根的`commands`。全部数据来自给定假设；没有额外的真实剧本参数。可选`--warmstart`仍为三牌命令数组的数组，须遵守当前队长顺序；排序错误的历史种子会被拒绝。

### 两世界结构校准

源码指纹`7c083674…`。使用FS01第1轮第1天的6角色初始出牌根；两个假设互换女学生／巫女的关键人物与杀人狂身份，其余设置相同。人为指定原质量2/5和1/2，剩余1/10保持未知；这组质量用于结构校准，未声称来自真实后验。红方368640套，两个世界各720套黑牌，固定跳过可选技能政策，初始化两套合法历史防守候选。

| 后端／串行预算 | 返回全域界 | 收益计算次数h0／h1 | 停止原因 |
| --- | --- | --- | --- |
| cached／10秒 | [0,1] | 84／2 | time_limit |
| cached／60秒 | [0,1] | 447／2 | time_limit |
| reference／10秒 | [0,1] | 103／2 | time_limit |
| reference／60秒 | [0,1] | 600／2 | time_limit |

两个cached档位均有一个能力树单元格在截止时保持未知；reference60秒虽无未完成单元格，未遍历列仍保留未知，两后端均未完成首个世界全部720列。随后4进程、reference后端与原生`Game.transition`独立检查全部1440列：返回的共同红方纯策略在两个世界各自保障1，已覆盖部分的精确保障为9/10，加上遗漏质量后区间为[9/10,1]。这是给定假设质量下的当日策略保障，未证明真实后验或整局胜率；遗漏质量使0.01的全域gap无法闭合。

因此该校准根的主要问题是完整检查的开销，返回策略本身已有安全防守。有限预算下不把未完成检查填成1的处理正确。该根reference60秒比cached多完成约34%的收益计算，当前缓存未形成提速；仍需分别统计授权历史序列化、缓存命中及引擎成本，不能把单根结果外推到全部剧本。独立并发核验不作串行性能基准。
