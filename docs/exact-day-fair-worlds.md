# 公平多世界博弈：分块求解与授权续演（T0.4，进行中）

本页记录T0.4有限世界内核的初期实现与校准。当前已有分块精确LP、Double Oracle、原质量及真实FS固定观察政策；后续 [公开联合后验桥](public-posterior-day.md)已接入矩阵／witness管线，并增加可选[兼容隐藏历史重放](compatible-history-day.md)。长历史增量维护及信息集能力优化仍待完成，默认AI和大厅入口保持不变。

## 1. 共同红方策略与分块黑方回应

每个世界h提供自己的收益矩阵`A_h`和原概率质量`p_h`。红方统一使用x，黑方按其已知世界分别回应：

```text
maximize_x sum_h p_h min_b sum_r x[r] A_h[r,b]
```

同一个x在所有世界使用，世界内不能分别优化红方行动再平均。黑方的本日暗牌也不能在看到红方本次私有随机抽样后重选；揭牌后的能力才按规则响应实际红牌。

受限博弈按世界保留少量黑方列。精确LP加shift使收益B全正后，求：

```text
maximize t
sum_h,b p_h B_h[r,b] z[h,b] <= 1       每个共同红方行r
sum_b z[h,b] = t                       每个世界h
z >= 0, t >= 0
```

每个等式用两条零右端不等式表示，初始松弛基可行，使用有理数Bland单纯形；零右端的退化情况同样受防循环规则约束。黑方条件分布为`z[h,:]/t`，红方分布由前R条约束的对偶价格除以t得到，值为`1/t-shift`。原始／对偶目标与原收益块的鞍点约束全部独立复核。

规模为`R+2H`条约束、`1+sum(C_h)`个变量，无须枚举`product(C_h)`套黑方条件策略。新增通用可行松弛基LP组件供T0.3与T0.4共享，没有新增依赖。只覆盖当前受限矩阵的LP解仍需完整域回应核验。

## 2. 按需收益与完整域回应

`BayesianDoubleOracle`维护共同红方行和每世界各自的黑方列、精确收益LRU缓存；逐世界独立找黑方最优回应，红方对所有世界条件策略的加权支持找同一个最优回应。完整黑方检查成本按各世界域规模求和，未物理展开条件策略笛卡尔积。

新增黑方列与本世界当前列下的收益底线比较，不能直接与全世界平均值比较；不同世界的局部收益本就可以不同。未知单元格不缓存为0，预算中断和部分求和遵循T0.3的可靠区间约束。历史最强L及对应x、历史最强U及对应条件策略分别保存，允许同一不可变模型续跑。

## 3. 原后验质量与遗漏质量

输入质量必须为正，允许总质量`m<=1`。所有全域界使用原`p_h`，遗漏的`1-m`按声明的收益范围补入区间：

```text
L = covered_L + (1-m)*utility_min
U = covered_U + (1-m)*utility_max
```

受限LP内部为缩放数值使用`p_h/m`，结果、最优回应加权和证书都恢复原质量；不会丢弃未纳入世界后直接宣称胜率更高。测试中覆盖0.9质量的全安全世界只能给[0.9,1]，仍保留0.1未知。

采样粒子总权重为1也不证明完整后验覆盖。`belief_domain_complete`须由上游明确声明；世界输入来自调用者，当前工具不能自动证明它就是真实完整后验。CLI的`--complete-posterior`是调用者断言，报告单独记录该来源。未核实的经验分布只支持该有限模型的结论，不能认证原后验或真实剧本胜率。

## 4. 固定授权续演

`FixedPolicyDayGame`采用固定红方政策，黑方仍搜索全部合法日末能力。政策只收到不可变`InformationState`，内容为：

- 团队授权视图，含公开事件历史、合法私密答案及三席手牌。
- 红方自己的命令记录，保留自己的能力选择记忆。
- 当前红方合法命令菜单。

输入没有私有`Game`、真实世界标签、隐藏身份、私密能力使用标志或隐藏黑方命令数量。不同世界的根必须有相同授权信息和同一版本的完整红方行动域，否则拒绝组合。

当前政策`PublicSkipOptionalPolicy`v2识别原生`next`及兼容`pass`，优先跳过可选能力，其余选规范顺序首项，作为简单、确定性的公平续演基准，棋力有限。v1仅识别`pass`，原生菜单中可能选择首个技能；历史v1报告不代表v2的行为或棋力。自定义政策须为纯函数并冻结版本；求解期间检测版本变化。未来可以冻结更强的观察政策，或单独求信息集能力策略。当前固定政策模型的最优值不代表全部合法红方能力策略的最优值。

自定义固定观察政策的值缓存同时包含完整规则状态、政策版本和授权历史输入，不能沿用仅按物理状态缓存的开眼最优值。旧`information_key`中的保守历史区分可用于内部缓存审计；政策输入不使用隐蔽命令占位符／决策序号作为信息，以免将看不到的操作数量变成选招依据。内置纯菜单政策另有下述审计特化。

### 4.1 审计菜单依赖特化（2026-10-18）

`PublicSkipOptionalPolicy.choose`只读取规范排序后的合法菜单：有`pass`／`next`则优先跳过，否则选第一项。因此在**精确的该政策类＋精确的日末0/1求解器类**中，可以仅构造菜单的不可变输入，并用完整规则状态、政策版本和本日位置缓存标量值。相同完整规则状态决定后续合法菜单与日末效用，政策选择对历史不敏感，故逐层选择／min结算保持相同值。

这项优化没有删除游戏事件、知识、资源或自己的记忆；根的共同授权信息检查也保留。省略只发生在该已审计政策的续演输入与标量值键。自定义政策、同版本名的包装政策、政策子类或求解器子类一律保留完整授权历史。两种缓存均只适用于`day-survival-v1`，不能用于T1的信念／信息／资源续局值。

`policy_context`报告`mode`、完整／菜单输入次数和值键次数，`continuation_cache`报告命中与条目数。`--generic-context-baseline`用相同行为的通用包装政策走保守路径，作为验证与计时消融，不增加大厅AI模式。

- 共同红方行动的反例：两个世界各自开眼能得1，合法共同策略只能得1/2。

- 12世界×2黑牌：分块LP为26约束／25变量，最后黑方回应最多检查24个候选，无须4096套条件策略。
