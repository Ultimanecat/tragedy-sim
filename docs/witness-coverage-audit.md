# FS / BTX witness 覆盖审计

本页把规则效果与主人公实际可观察到的现象逐项对应。目标不是把所有相关性都写成硬结论，而是：

组件装配、规则集复用和新增规则集流程见 [Witness 组件架构](witness-components.md)。
下一批待实现候选、优先级与消融顺序见 [Witness 候选清单](witness-candidate-backlog.md)。

1. 所有合法解释都支持时才加入硬约束；
2. 仍有其它解释时只加入可校准的软因子；
3. 同一因果链的多个日志不得重复放大后验；
4. 每个新增来源均可用 `--disable-witness-source SOURCE` 单独关闭，并做同种子消融。

硬 witness 的验收必须包含正例、反例、旧回放兼容和“真实世界不被删除”测试。软 witness 还要比较候选排序、置信度校准与最终猜测，不能只看胜率。

## 事件逐项审计

FS/BTX 的谋杀、不安扩散、自杀、医院事故、远距离杀人、失踪、散播、邪气污染与蝴蝶效应均已有“发生/未发生 + 当日阈值快照”；自杀、失踪的直接目标，以及谋杀/蝴蝶效应目标的区域关系，也已进入当事人硬约束。下一轮审计按以下顺序进行：

- 发生事件：事件种类、日期与公开阈值已经是硬约束；补测替补打工仔、死亡/未登场当事人和 AI 特殊阈值。
- 事件效果：利用公开目标、位置和计数物变化区分当事人候选，但选择性效果不能把“未选择”写成硬否定。
- 未发生事件：低于阈值是正向软支持；达到阈值仍可能因死亡、缺席或防止效果未发生，保持未知。
- 同一 `incident_status`、后续计数变化和 `incident_ended` 属于同一因果链，软分数必须分组封顶。

## 建议实施顺序

1. 已完成：接受可拒绝好感能力排除强制拒绝者，并建立按 source 消融开关。
2. 已完成：建立正常轮回结束的**完整合法解释集合**；硬排除完全不能解释失败的世界，同时在候选解释之间保留软权重。
3. 已完成邪教徒忽略禁止密谋、求爱者/杀手导致的日末主人公死亡，以及 BTX 关键能力死亡批次；下一步扩大种子并审计事件效果目标。
4. 事件效果目标与当事人位置关联。
5. 跨轮回的病毒、因果线和不安定因子联合 witness；只有确实需要时才引入跨维相关粒子。

每一步先跑构造反例与全部记录剧本“真实世界硬兼容”测试，再跑相同种子启用/关闭对照。报告至少包括主人公胜率、最终猜测正确数、硬候选空间、反向胜负样本和耗时。
