# 后续开发路线图

本文记录角色补齐之后的中长期工作。现有 Web、局域网房间、SSE、随机 AI、定式剧作家 AI、朴素与优化 MCTS
继续作为可运行基线；新功能仍通过 Python 后端的结构化行动、状态转移和信息视图接入。

## 实施顺序

```text
阶段 A：补齐正式角色（35 名，已完成）
        ↓
阶段 B：录入官方剧本（首批 22 个已完成，继续等待资料）
        ↓
阶段 C：策略搜索与信念 AI
        ↓
阶段 D：云端部署与远程联机（需要 ECS 实例）
```

阶段 B 依赖人工资料，可以在等待资料时先开展阶段 C；阶段 D 在确定云主机、域名和部署预算后进行。
每个阶段都不得在前端复制规则，AI 和网络客户端只消费后端提供的公开视图与 `ActionOffer`。

## 阶段 A：补齐正式角色（35 名，已完成，2026-09-15）

在现有 19 名角色基础上补齐通用正式角色：

- [x] 神格（本地中文卡名为“神灵”）
- [x] 大人物
- [x] 学者
- [x] 幻想
- [x] A.I.
- [x] 黑猫
- [x] 转校生

每名角色需要同时完成：

1. 卡面基础数据、好感能力、固有特性和剧本编写约束；
2. 所有适用规则集中的结算与信息边界；
3. JSON catalog、中英日术语、React 展示和 WebP 素材映射；
4. 正常发动、空发动、限次、拒绝、死亡和跨轮回等边界测试；
5. 全量 Python、Web 测试及生产构建。

推广角色和脚本集附加角色暂不属于本阶段；在上述七名稳定后另行排期。

随后已按官方角色总表补齐小女孩、教主、模仿者、御神木、妹妹、临时工/临时工？、从者和上位存在。
按项目范围排除 UP 主与仙人；临时工？作为临时工死亡后的替换面实现，不计额外初始登场位。当前 catalog 共 35 张角色卡。

## 阶段 B：录入官方剧本（进行中）

由用户提供可核对的官方剧本图片或数据。每个剧本人工录入 `scenarios/`，至少双重核对：

- 规则集、规则 X/Y、天数和轮回数；
- 登场角色与身份，包括局外人、A.I. 等特殊配役约束；
- 事件日期、事件类型、当事人与公开伪装信息；
- 公开特殊规则和剧本专属设置。

录入后使用严格校验器加载，并为每批剧本建立目录测试；不从来源不明的网络转录直接导入。

首批已根据用户放入 `references/` 的图片录入并验证 22 个剧本：FS 2 个、BT/BTX 11 个、MZ 4 个、MC 5 个。
大厅目录自动发现这些剧本并显示卡面允许的轮回数范围；当前以 JSON 的 `loops` 值作为默认轮回数。剩余官方剧本仍需
继续由人工提供和校对；集中完整试玩尚未完成。

## 阶段 C：更强的 AI

按可验证的能力逐层升级，始终保留随机 AI 和定式 AI 作为基线：

### C1：搜索基础设施与评估基准（已完成，2026-09-15）

- [x] 可复现随机种子、思考时间和节点预算；
- [x] 状态克隆/转移性能基准、终局奖励和有界启发式局面评价；
- [x] AI 决策追踪只进入进程内调试记录，不向对手或 replay 泄露；
- [x] 固定剧本自对弈胜率/耗时基准和真实规则终局回归测试。

### C2：完全信息 MCTS（已完成，2026-09-15）

- [x] 先供剧作家 AI 与调试基准使用，并在局域网大厅作为独立 AI 类型提供；
- [x] 使用后端 `action_offers` / `transition`，不解析界面文本；
- [x] 将主人公视为对抗方，在 UCT 中最小化剧作家收益；随机 rollout 覆盖阶段内能力顺序与规则集扩展行动。

当前大厅预算为 24 个树节点、rollout 深度 12；命令行基准可自行扩大。墙钟限制仅作为超时保险，要求逐次完全复现时应只
使用固定节点预算。MCTS 不向主人公开放完整状态；后续 C3 将用与观察一致的隐藏世界采样替换根状态来源。
性能剖析、无损优化与尚未实施的剪枝候选见 [MCTS 性能诊断与后续优化计划](mcts-performance-plan.md)。

朴素 `mcts_mastermind` 始终保留为可在大厅选择和基准工具中对照的基线；新增
`optimized_mcts_mastermind` 使用轻量搜索副本、内部原始命令、强制行动快进、渐进拓宽及可审计的行动先验。
第二批优化增加实际落子后的匹配子树复用，并提供八规则集统一延迟/内存矩阵基准；Trace 会记录复用节点数，仍只存在
服务端进程内。

第三个独立版本 `strategic_mcts_mastermind` 已加入剧本路线扩展先验和剧作家策略 rollout，并在 FS/BTX 65 局低预算基准中
达到 95.4%。旧朴素/优化模式继续保留。下一步先增强主人公公开信息策略（事件防守、关键角色保护、好感能力），再重跑同一矩阵。

`defensive_protagonist` 已完成上述确定性防守并作为独立房间选项保留；同矩阵下剧作家仍为 61/65（93.8%），仅少一胜且
平均对局明显变长。下一主人公版本应根据公开揭牌历史估计剧作家关注目标，形成不读取真实 setup 的轻量风险分布。

### C2.5：剧本条件化局面估值（进行中；FS/BTX 第一版已完成）

当前 `MastermindEvaluator` 虽然接收完整 `game`，能够读取剧本设置和当前状态，但只是跨剧本共用的线性启发式；在多数
rollout 无法到达终局时，它实际承担了主要棋力判断，因此需要升级为显式的 `V(setup, state, perspective)`：

- [x] 将剧本静态设置预编译为 `ScenarioEvaluationContext`：规则 X/Y、身份配置、事件日程、失败路线、角色阈值和特殊规则；
- [x] 将当前局面提取为与规则实现解耦的 `PositionFeatures`：各失败路线进度、距离截止日、行动资源、角色存活、公开知识和
  当前结算时间点；
- [x] 为 FS/BTX 的主规则、身份路线、事件截止和规则 X 建立可组合贡献；其他规则集暂时明确回退旧估值；
- [x] 对 FS/BTX 阈值型效果使用非线性“悬崖”评分；路线依赖与跨路线概率校准仍待深化；
- [x] 标记稳定结算时间点与尚未翻牌/尚未完成强制能力的中间状态，为后续稳定边界 rollout 提供依据；
- [x] 输出私有、可审计的贡献明细，说明失败路线、截止日、轮回进度和主人公资源/知识；不进入玩家视图或 replay；
- [ ] 完全信息 MCTS 在真实 setup 上评价；ISMCTS 必须分别在每个采样 setup 上评价后按粒子权重聚合，不能读取真实 setup；
- [ ] 用更深搜索或完整终局样本校准分数与胜率的关系，并按剧本留出测试；暂不直接采用需要大量对局数据的神经网络价值模型；
- [x] 为 FS/BTX 建立终局精确性、局部单调性、跨阶段标记和规则集特例测试；
- [ ] 增加深搜索回报相关性、胜率校准与特征组消融测试，再把当前权重视为稳定版本；

FS/BTX 第一版已接入 `optimized_mcts_mastermind`，朴素 MCTS 仍使用旧估值作为固定基线。自动测试覆盖全部 13 个已录入
FS/BTX 剧本的逐步评价直至真实终局，并另行覆盖未录入的 FS“复仇火种/最黑暗剧本”、五种主规则阈值、角色路线、
事件过期、轮回进度、公开知识与中间阶段。当前仍属于规则驱动初值，尚未用深搜索回报完成胜率校准。

推荐接口是“setup 编译一次、state 高频评价”：`compile(script, ruleset) -> evaluator(state, perspective)`。终局仍严格返回
`±1`；非终局分数解释为经校准的剧作家胜势，范围保持有界。主人公的信息价值和探索奖励应放在 ISMCTS 选择策略中，
不与真实局面胜率混成同一个不可解释的分数。

### C3：ISMCTS

- [x] 定义只从主人公投影构造的 `PublicEvidence`，忽略剧本 ID、标题和未揭示秘密；
- [x] 增加目录粒子采样器，并按公开登场角色、事件日程、已知身份/当事人/规则过滤；候选为空时不回退真实剧本；
- [x] 按规则 X/Y 身份槽、角色数量上限与事件约束生成组合粒子，并由严格剧本校验器逐个验收；
- [x] 将标准粒子物化为真实游戏，并用合法公开命令重放和语言无关的最终公开快照淘汰矛盾粒子；
- [x] 对未公开行动枚举粒子内合法后继，仅保留公开快照一致的行动；观测等价的暗牌不会被错误区分；
- [x] 真实引擎在每次决策后为各主人公记录语义快照摘要；摘要不含命令，模拟/搜索副本不会追加真实观察历史；
- [x] 粒子过滤器可按观察摘要推进多个隐藏世界，按完整私密状态去重，并用固定种子蓄水池采样限制宽分支规模；
- [ ] 从整局观察检查点增量维护房间级粒子集合；已知公开命令只作为缩小分支的优化；
- [ ] 为命令增加明确的公开/未公开标记；未翻开的当日暗牌必须重新采样，不能从完整 `history` 复制；
- [ ] 将规则结算 Observation 约束接入增量粒子更新，而不只在重放末尾比较完整快照；
- [ ] 在信息集节点聚合不同隐藏世界的访问统计，接入主人公 ISMCTS 策略和大厅选项；
- [ ] 使用公开现象、未出现的强制效果及对手行动更新粒子权重和可行世界集合。

主人公不能访问真实身份、真实规则、当事人或内部因果 Trace。目录采样主要作为信息边界与已知剧本回归工具；正式搜索
使用不查询目录 ID 的组合粒子。当前组合生成覆盖普通角色配置；需要剧本专属角色设置的粒子将在公开设置证据结构化后补齐。

### C4：带玩家猜测模型的信念 AI

- 显式维护身份、规则和事件当事人的概率分布；
- 区分规则必然现象、玩家可选行为与玩家失误，避免把“没有发动”当作硬证据；
- 为其他玩家建立嵌套但有界的信念/策略模型；
- 可选择不同风险偏好和玩家熟练度模型，并输出可审计的决策依据。

ISMCTS 和信念更新必须只使用该座位可见的结构化 Observation。若需要改变核心协议，先增加架构测试，
不得通过读取完整剧作家状态绕过信息集问题。

## 阶段 D：远程联机与 ECS 部署

需要用户提供或授权使用一台公网 ECS 实例。第一版沿用现有房间、令牌、SSE 和服务端权威结算，增加：

- Linux 服务进程、反向代理、HTTPS、域名和自动重启；
- 防火墙/安全组只开放 HTTPS 和必要管理端口；
- 房间限流、请求体限制、日志轮转、健康检查和基本备份；
- SSE 经过代理时的缓冲关闭、空闲超时和断线重连验证；
- 部署配置与密钥分离，仓库中只保存模板；
- 手机公网访问、刷新恢复、长局断线和版本升级的人工验收。

计算量较低时，小规格 ECS 足以支撑少量私人房间；启用大量 MCTS 后，需要把 AI 任务并发、思考预算和
资源上限纳入容量评估。暂不建设公共账号、匹配、聊天或对抗恶意作弊系统。

## 提交与验收纪律

- 阶段 A 可按机制相近的角色分批提交，每批保持可运行；
- 官方剧本按来源批次提交，数据与引擎修复分开；
- AI 的搜索器、信念模型和策略调整分别提交并保留基准数据；
- 云部署配置不得包含令牌、私钥或真实密码；
- 每个纵向切片必须通过 Python 全量测试、Web 测试和生产构建。
