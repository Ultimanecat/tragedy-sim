# 身份内暗牌保守估值（2026-10-15）

## 问题与实现

BTX04 的已知身份回放中，第二天关键人物可能被放密谋 +2，原算法仍选择三张友好牌。当天不会立即失败，反例搜索的当日截止点也无法发现轮回末规则 Y 的失败。轻量排序把少数危险暗牌的状态成本平均后，友好准备收益超过了防守收益。

开眼新增可选 `dark_state_policy="mean"|"worst"`，默认保持 mean。`worst` 同时用于联合候选排序及真实续演后的状态估值：在同一身份／剧本假设的暗牌场景中取最低状态分。当前存活比例仍为第一排序项，原来的危险度、限次牌成本和定式技能路线检查保持。该开关没有增加跨日搜索深度，也没有提供暗牌完备证明。

`JointThreatRanker` 的 worst 模式拒绝混合身份或剧本，追加场景时也检查此边界。公平多世界迁移应先在各身份假设内评价暗牌，再按后验质量聚合身份；压力场景的数量不能作为身份或暗牌后验概率。当前公平主线及黑方内部回应未切换。

另修复开眼暗牌重建中的运行时身份遗漏：病毒已将平民变成杀人狂时，脚本知情的开眼样本保留当前身份。只读取明确授权的当前身份，不读取今日黑牌或剧作家私密手牌；公平 helper 的 `script_aware_rollout=False` 不进入这条同步分支。公共视图与正式游戏均不修改。

## 验证与复现

专项覆盖均值与最坏值的差异、混合身份拒绝、BTX04 提前挡密谋以及病毒身份同步。重建的 BTX04 第二天根中，两版当前日都存活 31/31；均值选择三张友好牌，保守版选择禁止密谋保护关键人物。这个单根结果仍需完整对局检验。

对弈工具提供 `--state-ablation`，固定候选、技能及未来事件估值，仅比较 mean／worst；完整 replay 和公开真值仍逐局审计。示例：

```powershell
python -X utf8 -m benchmarks.ai_oracle_defense_validation --scenario official-btx-04-young-womens-battlefield --candidate joint_counterexample --future-incident-policy impact --state-ablation --workers 4 --output references/dark-state-10seeds.json
```

省略 `--seed` 使用 0–9。节点限制代表固定候选预算，额外反例和技能模拟仍独立计数，不称等 CPU 时间。并发计时只用于运行成本观察。

## 公平多世界迁移验收

1. 假设键包含当前／初始身份、剧情及当事人等影响结算的条件，不能只按角色边际矩阵相同来合并世界。当前开眼的完整 scenario 与运行时身份键只能用在已知身份作用域。
2. 保存原始后验样本及质量；暗牌压力分支和新增反例另存。重复身份样本的质量累加，新增压力分支不得增加该身份的后验质量。
3. 同一三牌组合先在各假设内评价暗牌及黑方能力路线，再按原后验质量聚合假设。所有组合使用同一假设与共同压力集合；每个假设各自选好牌后再平均会高估可实现收益。
4. 公平入口仅接收授权视图和采样假设。沿用完整 matcher 与运行时知识语义；禁止通过开眼重建函数读取真实当前身份、剧情或今日黑牌。
5. 把联合候选覆盖与状态聚合分开消融；比较当前公平 sampled／adversarial_guard 与新路径，并保留开眼作为行为诊断。需要完整对局和同种子差异回放，不能用单根防守通过替代棋力验收。

短名单、有限暗牌探测与定式续演仍可能漏掉危险；保守聚合只能降低已覆盖危险被均值稀释的问题。迁移时同时记录身份组数、原始质量、额外攻击数、候选／模拟工作量及回退原因。

## 迁移前成本诊断

指纹冻结期间另对 BTX04 第一天固定根做只读 cProfile，不改对弈源码。31 个暗牌场景、4 个引擎候选，完整枚举 123852 个合法三牌，候选效果／资源代表 42505 个；联合排序约占带 profiler 总时间的 85%，轻量投影与评分 523523 次，真实定式续演 248 次。

递归冻结轻量模型全部字段后，31 个模型仍有30个不同；仅合并完全相同模型的收益有限。公平迁移的性能优先考虑无阴谋家／无幕后黑手时避免空压力累加，以及静态身份特征预编译，不能靠删掉后验身份或改变样本权重节省时间。进一步实施前仍需逐计划等价和完整对弈决策／replay对照。

诊断脚本、`.prof` 和输出分别在忽略目录 `references/ai-calibration/2026-10-16/profile_dark_state_root.py`、`profile_dark_state_root.prof`、`profile-dark-state-root.txt`。运行与对弈并发且开启 profiler，约30秒的诊断耗时不能充当正常响应基线。

隔离原型进一步比较六剧本、早期／末日、每状态128三牌×3暗牌场景，4608次评分完全相同。只跳过空压力累加的信号较弱；加上按当前身份与城市／学校密谋阈值缓存的身份成员集合后，40倍重复批次原3.35／3.44秒，原型3.11／2.76秒，仍为并发诊断，不作正式加速承诺。原型未合入生产源码，报告 `prototype-empty-pressure.txt`、`prototype-compiled-pressure.txt`。

另发现独立排序错误：跨轮回重复计划惩罚直接扣存活率，31场景时原本31/31的重复计划得0.94，30/31新计划得约0.968，会错误选后者。隔离脚本已用真实选择函数和受控续演分数复现。该问题与暗牌保守聚合分开修复／验收；40局仍使用原冻结源码，不能用后续修正版解释本批结果。
