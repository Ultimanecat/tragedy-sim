# BTX 日末截断估值校准审计

当前黑方联合搜索到达日末、且尚未出现真实胜负或最终猜测时，使用单日局面启发分。该分数用于候选排序，没有被训练成胜率。审计入口：

```powershell
python -m benchmarks.ai_cutoff_calibration --games 4 --seed 0 --strategy fixed --protagonist-nodes 8 --protagonist-ms 1000 --exact-penultimate
```

采集每次 `day_ended` 后进入下一天的非终局状态；每条记录保存红方日末分、硬角色域熵、轮回／日期。对局结束后标注「本轮存活直接赢」「最终猜测赢／输」等终局类型。每局的全部日末记录总权重相同，防止长局因记录更多而主导 AUC。倒数第二天可选运行红方的完整身份 MAP 求解，记录当时答对人数与耗时。`--json` 输出逐局、逐日数据。测试用的对手、种子和预算须和结果一起保存。

2026-09-24 首轮固定策略黑方数据：BTX02、BTX09 标准版各 seed 0–3；粒子主人公每次 8 节点／1 秒。每剧本均有 2 局存活直接红胜、2 局终猜黑胜，合计 80 个日末截断点。按整局红胜的匹配权重 AUC：BTX02 日末分 **0.660**、负硬域熵 **0.278**；BTX09 日末分 **0.457**、负硬域熵 **0.530**；合并后日末分 **0.558**、负硬域熵 **0.443**。在现有样本上加 `-0.02 × 熵` 后的合并 AUC 为 **0.558**，没有可见增益。倒数第二天 20 个完整身份 MAP 探针的最大耗时约 **1.08 秒**；其答对比例对“整局红胜”的 AUC 为 **0.206**。此反向关系来自两类不同的胜利路径，不能解读成“了解更多身份降低红方胜率”。

解释：一个红方仍不知道多数身份的局面，后续可以直接存活到最后一天并获胜；一个反复失败、积累了较多证据的局面，即使终猜多答对几个角色也可能整体失败。局面压力和终猜信息分别描述不同风险。若目标是整局胜率，估值应分别预测「在剩余轮回中直接存活获胜」和「走到最终猜测后整套身份全部猜对」，再按到达各终局的概率组合。要先用更多剧本、不同强度黑方和独立种子校准这些条件概率；不能把目前的启发分或身份答对比例线性映射为胜率。

目前生产搜索只在真实模拟进入 `final_guess` 时以实际整套猜测计分；早期仍保留原日末启发分和可关闭的小幅熵排序项。首轮样本不足以支持修改生产权重。下一步应收集黑方混合策略与不同轮回数的数据，按终局路径分层，并针对同一黑方根候选做后续策略的成对延伸，减少实际对局轨迹与反事实候选之间的分布偏差。

同预算的信念联合黑方补充样本：BTX02、BTX09 标准版各 seed 0–2，黑方每步 16 节点／1 秒，红方仍 8 节点／1 秒；六局全为终猜失败的黑胜，分别得到 13、36 个日末点。该对手更强，但没有红胜样本，AUC 应报告为不可估计，不能把全黑胜解释为估值已被校准。后续要纳入其他黑方风格或扩大红方预算，产生两种结果后再做强黑方下的辨别测试。

## 双路径离线原型

`--path-cv` 增加三段条件概率：直接存活获胜、未直接获胜后进入终猜、进入终猜后整套身份猜对。组合的整局红胜概率为 `P(直接赢) + [1-P(直接赢)] × P(进入终猜 | 未直接赢) × P(终猜全对 | 进入终猜)`。前两段使用日末分与局数／日期进度，终猜段使用公开硬身份域熵与进度。每局记录权重之和为 1；同一 seed 的所有剧本、策略与日期一同留出，用剩余 seed 拟合，再与单头胜率模型、常数先验比较 Brier 分数。原型仅存在于 `benchmarks/`，没有接入对局搜索。

复现命令：

```powershell
python -m benchmarks.ai_cutoff_calibration --scenario official-btx-02-traditional-ensemble-murder-easy --scenario official-btx-09-those-with-antibodies-easy --games 3 --strategy fixed --protagonist-nodes 8 --protagonist-ms 500 --path-cv
```

2026-09-24 探索性运行：6 局、88 个日末点，3 局直接存活红胜、3 局终猜黑胜，**没有终猜红胜**。留出 seed 的 Brier：双路径 **0.439**，单头 **0.465**，常数先验 **0.380**；双路径 AUC **0.049**。由于仅 3 个 seed、终猜正例为零，且该次运行与全量测试共享 CPU、限时搜索轨迹出现波动，这些数字只用于暴露样本不足与校准失败，不能据此宣布某模型更强。倒数第二天的身份正确比例即使提高，也不等同于「整套全对」概率。

下一步先构造覆盖两类红胜、终猜黑胜与其他黑胜的独立样本：补充多种黑方回复风格、红方预算和标准／Easy 轮回；基准顺序运行以减少限时漂移。再按剧本和 seed 双重留出验证，比较概率校准和真实黑方根候选排序。只有双路径持续优于单头及常数基线，且终猜分支拥有足够正反例，才考虑把它接入黑方搜索。
