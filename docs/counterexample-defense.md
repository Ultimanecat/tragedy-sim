# 候选条件化联合反例搜索（2026-10-15）

## 实现和入口

两种开眼红方支持可选 `candidate_policy="joint_counterexample"`；CLI 使用 `--oracle-candidate-policy joint_counterexample`。默认保持旧配置。明牌开眼今日牌面已知，沿用 `joint_threat`；新增暗牌分离只在暗牌开眼运行。公平矩阵红方尚未接入。

`tragedy_sim/defense_counterexamples.py` 接收一个假设世界、授权视图、共享三牌空间和候选集：

1. 沿用单因素／固定联合模板的共同场景，枚举公开合法暗牌匹配，保持实体牌互异、公开牌面和弃牌等限制。
2. 对每套红方候选扫描轻量联合威胁，按红牌结算后的角色位置／计数寻找危险黑牌配合。
3. 用真实引擎检查高风险分支，若任一适用定式技能路线导致当日失败，将该整套黑牌加入共同场景。
4. 重新排序完整声明三牌域，再检查新候选；最多 8 轮、16 次引擎攻击探测，并遵守软截止。
5. 在最终同一组共同场景上评价入围候选，不复用旧场景集合的存活分数。

这是敌对行动搜索，不增加身份／当事人／暗牌后验质量，也不产生公开 witness。组件拒绝混合身份／当事人假设输入。未来公平版需在每个身份假设内分别找反例，并保留原始身份后验权重。

## 正确性边界

- 只有引擎确认的当日失败才添加反例，轻量风险分不构成硬约束。
- 检查过但未确认的分支按完整席位／牌／目标缓存，保留限次牌所有者差异。确认反例按整套黑牌去重。
- 日末攻击探测不受更长 rollout horizon 的终猜获胜掩盖。正式候选仍按调用者 horizon 评价。
- 公开所有暗牌匹配被轻量扫描，不代表全部匹配被真实引擎验证；轻量模型可能漏风险。`complete_engine_scan` 保守保持 false。
- Trace 明确区分合法匹配数、轻量检查、真实探测、加入反例数、迭代次数、停止原因和具体被击败三牌。总引擎 rollout 数含分离探测，额外完整域扫描／排序投影另记。
- 首个共同评价批次仍原子完成；一次正在执行的模型编译、排序或引擎探测可以超过软截止。期限耗尽保留已有候选，未查到反例不宣称必胜。
- 只检查现有定式技能路线。完整技能行动树、自动必要防守证明及跨日准备仍未实现。

## 共同根验收

原 FS01 回放第 2 轮第 3 天：旧 `joint_threat` 的三牌在 504 套合法暗牌下存活 497 套，剩余 7 套涉及女学生加密谋、职员斜移靠近撤离后的女学生。

最初只迭代 3 轮，所选方案转而漏掉其它组合，穷举仅存活 462/504。这个开发反例表明有限共同场景全存活不能外推；因此保留有界迭代、显式不完备标记和独立全域验收。

8 轮上限下实际 5 轮、4 个引擎确认反例，找到全部 504 套暗牌均存活的三牌。每套检查三条现有定式技能路线，离线共 1512 次日末结算。决策约 7 秒；完整已知身份和定式路线限定下的覆盖达到 504/504，不外推身份未知或任意技能策略。版本化测试按回放的棋盘／手牌资源重建根局面，不依赖忽略目录的实验文件。

专项测试另含输入不变、暗牌真实牌面独立性、混合身份拒绝、到期保留候选、轻量误报不进入共同场景。最终同源重建原 replay 的报告为 `references/ai-calibration/2026-10-15/counterexample-common-root-final.json`；开发中间报告与正式报告分开。

## 完整对弈

固定种子 0–9、4 进程，在 FS01／BTX06 对比 `joint_threat` 与 `joint_counterexample`，节点预算相同，真实工作量增加，不能称等 CPU／等墙钟。行动获胜不计开眼终猜。工具可指定对照策略并保留 source／剧本指纹、任务续跑、完整 replay 及公开硬证据真值审计：

```powershell
python -X utf8 -m benchmarks.ai_oracle_defense_validation --scenario official-fs-01-first-script --scenario official-btx-06-secret-that-was-kept --baseline joint_threat --candidate joint_counterexample --oracle oracle_script --workers 4 --output references/counterexample-paired.json
```

同源 `88f882c2…` 的 40 局全部完成并通过 replay／公开真值审计：FS01 两版各 10/10 行动胜，BTX06 两版各 5/10，全部 20 个种子配对的行动胜负相同。这组没有胜率改善或退化，不把局部覆盖提升外推为整体棋力提升；保留实验开关。原始报告 `references/ai-calibration/2026-10-15/counterexample-hidden-paired.json`。

## 性能定位与下一步

对版本化失败根做 cProfile：总计约 24.16 秒，其中五轮 `ranked_bundles` 累计约 19.19 秒，约 79% 在重复联合排序；约 47.9 万次轻量世界评分。该计时受 profiler 影响，不能当普通响应时延。原始文件 `references/counterexample-profile-20261015.prof`。

可进行保行为的增量评分缓存：反例加入时只补算新场景，复用旧场景的结果。必须保留世界顺序、完整效果键、限次资源成本、缓存上限和实际投影计数。浮点和特别注意：分段均值／求和与一次 `sum` 可能有尾数差异，近分候选会因此换序；应保留有序值并统一汇总，或明确验证数值和决策等价，不能只比较胜率。

用户另提出按地点效果压缩暗牌：标准 FS／BTX 地点上的黑牌分密谋 +1、密谋 +2、无效；角色上的两张不安 +1 也有相同即时效果。应先枚举合法实体匹配再分组，保留每组真实成员及限次牌消耗。轻量投影可复用代表，实际引擎验证仍使用真实成员，不凭类别乘积生成组合，也不覆盖原始牌面、回放和未来手牌。不同牌面可能改变续演的随机种子及后续可用行动，不能只凭同日标记相同合并整个游戏状态。该项在当前固定源码对照完成后优先实现并检查保行为。

后续仍需分析相同种子的退化和医院事件的准备截止时间，先完善开眼防守，再迁移公平多世界。
