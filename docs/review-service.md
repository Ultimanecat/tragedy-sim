## 存疑待确认

以下问题没有形成确定性结论，需要维护者确认：

- 仓库没有 `web_contract*.py`。如果任务预期存在独立的 Python 契约模块，当前实现是把契约散落在服务代码、手写 `types.ts` 和 fixtures 中；是否需要补充生成式契约，需要架构负责人确认。
- `web/fixtures/protocol-v1` 的字段落后于当前服务端，但测试通过 `as unknown as` 强转。可能是 fixture 只用于前端行为测试，也可能本应作为协议快照；当前没有 CI 能发现两者漂移。
- `GameService` 的独立对局没有 TTL 或后台清理，只有房间层的 `_cleanup` 会删除对应 session。Web 端每新建/恢复一次对局都会留下旧 session，是否接受这种进程内增长需要确认。
- `client.roomUpdates()` 只更新 `roomRevision`，不更新 `gameRevision`；当前依赖随后 `refresh()` 更新，若 `refresh()` 失败会保留旧游戏 revision。是否有意依赖这条隐式顺序需要确认。
