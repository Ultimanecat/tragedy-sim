# ISMCTS 与 witness 证据设计

本文记录主人公 AI 从公开现象反推隐藏世界时采用的信息边界。第一阶段只覆盖 FS/BTX；接口允许后续规则集注册自己的
witness 编译器，而不要求搜索器理解每条具体规则。

## 为什么 witness 有用

ISMCTS 不应从真实 `scenario`、身份表或内部因果 Trace 开始搜索。它维护一组与主人公观察一致的隐藏世界，并在每次公开
结算后删除不可能的世界。witness 是“公开现象对隐藏世界施加的约束”，可在完整重放之前低成本缩小粒子集合，也能给以后
的概率模型提供结构化输入。

必须区分两类证据：

- **硬 witness**：规则必然推出的事实，可以直接淘汰矛盾粒子。例如公开身份、公开事件当事人、公开规则，以及在 FS/BTX
  中事件已经发生时，当事人在该时间点必须满足事件阈值。
- **软 witness**：只改变概率，不能把粒子权重降为零。例如剧作家反复给某角色放密谋，或没有发动一项可选能力。这些现象
  同时受策略、误操作和伪装影响，留给 C4 的玩家模型处理。

“没有看到某效果”尤其危险。只有规则证明该效果在当时是强制、公开且没有替代解释时，缺席现象才可成为硬 witness。
可选能力统一不得用缺席反推身份。

## FS/BTX 第一阶段

`FsbtxWitnessCompiler` 只从主人公 `view` 构造以下结构化证据：

1. `role_is`：已经公开的角色身份；
2. `culprit_is`：已经公开的事件当事人；
3. `plot_present`：已经公开的规则 X/Y；
4. `incident_happened` / `incident_not_happened`：公开事件记录。第一版仅用“发生”做阈值硬校验；“未发生”保留为现象，
   不直接淘汰粒子。

在此基础上加入两种**软 witness**：

5. `day_end_death_companion`：根据每轮初始位置和公开移动日志，重建某角色日末死亡时仍在同一地点的存活角色；
6. `loss_after_death`：记录一次公开死亡之后紧接着发生轮回失败。

这两类现象分别提高“同地点角色是杀人狂”及“死者是关键人物/挚友”的粒子权重，但绝不排除其他解释。死亡可能来自事件、
剧作家能力或别的角色特性，轮回也可能同时因另一条规则失败。软证据按通道设置独立上限，重复现象可以加强信念，却不能凭重复
次数变成伪硬约束。约束采样器只做带偏接受，仍保留少量不解释该现象的粒子；最终猜测同时考虑角色边际概率和整套身份对全部
软 witness 的联合解释力。

每条 witness 带轮回、日期、时间点和来源，方便调试时回答“哪个公开现象排除了这个世界”。matcher 采用三值结论：满足、
矛盾、未知；只有矛盾才删除粒子。

## 与 ISMCTS 的关系

搜索流程保持分层：

1. 从主人公投影生成候选 setup；
2. 用硬 witness 预过滤；
3. 将候选 setup 物化为粒子，并用公开观察推进；
4. 在同一公开信息集下聚合各粒子的行动访问次数和收益；
5. 后续再用软 witness 调整粒子权重，而不是改写规则真值。

当前主人公策略还使用一个明确、可调试的队内约定：同一对角色连续两轮出现上述同地点死亡后，当日领队负责移动其中一人，
下一位主人公对另一人使用禁止移动，第三人不再移动这两人；成功分开后优先锁住两人的移动。这不是隐藏信息推断规则，而是
由公开历史触发的行动策略，因此不会污染粒子真值。每次触发都会在 ISMCTS trace 中留下
`repeated_death_guard`、`repeated_death_companion_lock` 或 `repeated_death_coordination_hold` 原因。

评估函数始终接受“该粒子的 setup + 该粒子的当前状态”。不得先把多个 setup 混成一个虚构局面，也不得在主人公搜索中
读取真实 setup。

## 扩展到其他规则集时的挑战

FS/BTX 的固定因果关系较多，安全 witness 相对容易编写。MZ、MC、HSA、WM、AHR、LL 中存在伪装事件、替换身份、世界线、
额外资源和更多可选结算；固定事实更少、可变解释更多。扩展时仍复用同一框架，但每条新 witness 必须满足：

- 输入完全来自该座位的结构化 Observation；
- 列出所有规则替代解释，无法证明唯一时返回“未知”；
- 有正例、反例和“真实世界不得被误删”的回归测试；
- 规则集 matcher 与通用粒子容器、搜索树分离。

因此后续规则集可以少写 witness，不能为了收缩状态空间而写不可靠的硬推断。
