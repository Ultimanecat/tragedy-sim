# ISMCTS 与 witness 证据设计

本文记录主人公 AI 从公开现象反推隐藏世界时采用的信息边界。第一阶段只覆盖 FS/BTX；接口允许后续规则集注册自己的
witness 编译器，而不要求搜索器理解每条具体规则。

## 为什么 witness 有用

ISMCTS 不应从真实 `scenario`、身份表或内部因果 Trace 开始搜索。它维护一组与主人公观察一致的隐藏世界，并在每次公开
结算后删除不可能的世界。witness 是“公开现象对隐藏世界施加的约束”，可在完整重放之前低成本缩小粒子集合，也能给以后
的概率模型提供结构化输入。

必须区分两类证据：

- **硬 witness**：规则必然推出的事实，可以直接淘汰矛盾粒子。例如公开身份、公开事件当事人、公开规则，以及在 FS/BTX
  中事件已经发生时，当事人在该时间点必须满足事件阈值。
- **软 witness**：只改变概率，不能把粒子权重降为零。例如剧作家反复给某角色放密谋，或没有发动一项可选能力。这些现象
  同时受策略、误操作和伪装影响，留给 C4 的玩家模型处理。

“没有看到某效果”尤其危险。只有规则证明该效果在当时是强制、公开且没有替代解释时，缺席现象才可成为硬 witness。
可选能力统一不得用缺席反推身份。

## FS/BTX 第一阶段

`FsbtxWitnessCompiler` 只从主人公 `view` 构造以下结构化证据：

1. `role_is`：已经公开的**当前**角色身份。通常等同于初始身份；BTX 的“妄想扩大病毒”可能把本轮普通人变成杀人狂，因此“公开为杀人狂”必须同时保留“初始杀人狂”与“初始普通人且剧本含病毒”两种解释，不能直接改写最终猜测所需的初始身份；
2. `culprit_is`：已经公开的事件当事人；
3. `plot_present`：已经公开的规则 X/Y；
4. `incident_happened` / `incident_not_happened`：公开事件记录。规则引擎在事件判定瞬间把角色的公开计数物、在场／存活状态和护卫数冻结进公开日志，因此跨日、跨轮回后仍可用原快照校验候选当事人；旧 replay 没有快照时只返回“未知”，不拿当前棋盘倒推过去。“发生”是硬校验；“未发生”不能排除当事人，但若快照中的公开计数物低于其发动阈值，会给该当事人候选一个有限的软加权。

在此基础上加入**软 witness**：

5. `day_end_death_companion`：根据每轮初始位置和公开移动日志，重建某角色日末死亡时仍在同一地点的存活角色；BTX 同时记录该同伴此前是否公开达到过不安 3，使“病毒＋初始普通人临时变成杀人狂”与“初始杀人狂”都能解释强制死亡。
6. `loss_after_death`：记录一次公开死亡之后紧接着发生轮回失败；若当时都市密谋达到 2，也允许“因子临时获得关键人物能力”作为软解释。
7. `plot_pressure`：正常日末结算失败时，根据公开日志中已经满足的主规则条件调整概率。FS 目前覆盖学校密谋达到 2 对“守护此地”的支持；BTX 覆盖神社密谋达到 2 对“被封印的邪灵”的支持，以及本轮蝴蝶效应已经公开发生对“改变未来”的支持。它们都不能把其它同时存在的失败路线硬排除。
8. `joint_plot_role_pressure`：BTX 正常轮回末失败时，把“角色密谋达到 2”与“契约＋该角色为关键人物”、把“初始区域密谋达到 2”与“定时炸弹＋该区域起始角色中存在魔女”作为一个联合软因子评分，避免分别提高规则和身份后拼出没有因果关系的组合。
9. `role_pressure`：BTX 最终日正常失败时，友好不超过 2 且仍在场存活的角色支持“其中存在时间旅行者”。发动失败能力是剧作家的可选行为，也可能同时存在其它失败原因，所以它只加权、不排除。

这两类现象分别提高“同地点角色是杀人狂”及“死者是关键人物/挚友”的粒子权重，但绝不排除其他解释。死亡可能来自事件、
剧作家能力或别的角色特性，轮回也可能同时因另一条规则失败。软证据按通道设置独立上限，重复现象可以加强信念，却不能凭重复
次数变成伪硬约束。约束采样器只做带偏接受，仍保留少量不解释该现象的粒子；最终猜测同时考虑角色边际概率和整套身份对全部
软 witness 的联合解释力。

每条 witness 带轮回、日期、时间点和来源，方便调试时回答“哪个公开现象排除了这个世界”。matcher 采用三值结论：满足、
矛盾、未知；只有**硬** witness 的矛盾才删除粒子。角色/规则与逐日事件当事人的软评分分开归一化，避免偶然生成的当事人改变角色后验；重采样后的粒子在行动层等权，不能再次乘同一 witness 权重。

当前暗牌与剧作家放牌倾向不是规则 witness，而是另一条**行为后验**：公开揭牌按时间衰减形成“给某目标放某牌”的平滑先验，采样时仍保留均匀探索；日内暗牌粒子的经验分布、目标倾向和条件牌面概率分别记录在私有 trace 中。这种估计不意味着已知剧作家的固定策略，未揭牌或未发动能力也不能被当作硬否定。

## 与 ISMCTS 的关系

搜索流程保持分层：

1. 从主人公投影生成候选 setup；
2. 用硬 witness 预过滤；
3. 将候选 setup 物化为粒子，并用公开观察推进；
4. 在同一公开信息集下聚合各粒子的行动访问次数和收益；
5. 后续再用软 witness 调整粒子权重，而不是改写规则真值。

证据层不得直接返回行动，也不得覆盖 MCTS 的选择结果。重复死亡等现象只能改变候选世界的可行性/权重，行动变化必须来自
同一固定搜索预算在新世界分布上的正常比较。当前估值函数不奖励“多知道一项身份/规则”，rollout 也没有“故意输掉本轮换取
信息”的额外回报；将来若要研究信息价值，应作为搜索可见的长期胜率结果，而不是另加绕过规则终局的启发式奖励。

`PublicEvidenceLedger` 是两人局主人公团队 AI 独立持有的证据维度。证据编译、witness 匹配、粒子过滤/重采样和最终猜测都不计入
`SearchBudget.node_limit` 或 rollout 深度。`particle_count` 只是信念集合容量，不会扣减根行动访问次数；不论证据多少，根节点
仍按相同规则获得访问预算。Trace 分开报告硬/软证据数、观察更新数、粒子数和 MCTS iterations，避免把这些指标混为一种预算。

## 跨决策持续粒子

两人局中的团队 AI 只持有一份 `PersistentBeliefState`，共同控制 A/B/C。真实引擎在每次玩家决策后保存团队视角的状态摘要；
AI 下次行动时，从上次处理的位置逐条枚举相容后继并用蓄水池限制粒子数，而不是直接把当前公开棋盘覆写到一批全新 setup 上。
新增 witness 时再对存量粒子做硬过滤和有上限的软重采样。三名主人公分别推理的多代理模式尚未实现，未来将作为独立策略保留。

检查点不会复制服务端的完整命令，每个观察显式标为 `public / partial / hidden`。团队能看到自己控制的三张主人公牌；剧作家
行动牌只公开出牌者和目标，牌面仍需枚举并由后续摘要筛选。尚未逐类审计的非行动牌命令保守标为 `hidden`。ISMCTS trace 的
`belief_source` 会区分 `persistent` 与 `resampled`，并记录本次处理的观察数量。

主人公行动阶段按一个联合节点搜索三张牌。每次 iteration 在同一粒子中依次放置完整组合，再推进揭示与日末后估值；选中组合
只先向权威引擎提交当前逻辑席位的牌，其余两张存入私有计划，轮到对应席位时校验合法性后提交。计划失效则丢弃并重搜。
因此 `node_limit` 表示联合三牌组合的模拟次数，而不是三次单牌搜索预算之和。

评估函数始终接受“该粒子的 setup + 该粒子的当前状态”。不得先把多个 setup 混成一个虚构局面，也不得在主人公搜索中
读取真实 setup。

## 扩展到其他规则集时的挑战

FS/BTX 的固定因果关系较多，安全 witness 相对容易编写。MZ、MC、HSA、WM、AHR、LL 中存在伪装事件、替换身份、世界线、
额外资源和更多可选结算；固定事实更少、可变解释更多。扩展时仍复用同一框架，但每条新 witness 必须满足：

- 输入完全来自该座位的结构化 Observation；
- 列出所有规则替代解释，无法证明唯一时返回“未知”；
- 有正例、反例和“真实世界不得被误删”的回归测试；
- 规则集 matcher 与通用粒子容器、搜索树分离。

因此后续规则集可以少写 witness，不能为了收缩状态空间而写不可靠的硬推断。BTX 的小型身份×主规则关联已经证明可以作为局部联合因子加入，而不需要把身份、当事人和暗牌重新合成一个巨大粒子。
