# 跨日防守目标设计（长期投入方向）

大小姐第 5 天自杀是一个代表案例：失败不是当天才知道，而是前几天的计数已经把它推到阈值。只优化当天搜索，看不到这种跨日目标。

## 一、把事故变成防守义务

对每个未来事故生成 `IncidentObligation`：

```text
IncidentObligation
- day                 事故日
- kind                suicide / murder / hospital / ...
- culprit_candidates  已知或候选当事人
- counter             paranoia / goodwill / intrigue
- threshold           触发阈值
- current             当前计数
- required_margin     到事故日必须保留的安全余量
- lead_days           还剩几天
- preventable          是否可避免
- knowledge           公开已知 / 局部候选 / 完全未知
```

触发条件用规则引擎统一提取，例如：

- `suicide`：当事人不安 >= 角色上限。
- `murder`：当事人所在地有可杀目标。
- `hospital`：医院密谋达到阈值。

第一版只处理“计数阈值型”事故，先把大小姐自杀跑通。

## 二、反推需要多少防守

对每个义务计算需求：

```text
need = current + 预期黑方增量 - (threshold - 1)
```

如果 `need <= 0`，当前安全，但要把未来黑方出牌算进去。黑方增量用公开历史估计：

- 过去同角色、同事故日附近黑方出过多少 `p1`。
- 当前手牌中公开可见的限次牌。
- 保守模式取最坏情况，普通模式取期望。

得到“还剩多少点要降、最晚哪一天必须降”。

## 三、带截止日的资源调度

红方每天只有有限牌，且同一角色一天只能放一张。把防守当成调度问题：

- 每个义务需要 `need` 次 `p-1`（或移动、封禁等）。
- 每个行动占用一天的座位和一张牌。
- 黑方每天可能加压力。
- 目标：所有义务在截止日前满足，且不浪费稀缺牌。

第一版用简单规则：

1. 按截止日排序（EDF）。
2. 对最紧急义务保留 `p-1`。
3. 较远义务只在有余牌时提前降。
4. 同一天多个义务冲突时，优先死亡后果更严重的。
5. 事故日当天仍可补一次，必须把当天黑方出牌算进去。

这比“当天看到危险才防”多出 `lead_days` 的提前量。

## 四、处理未知当事人

公开信息可能只知道事故种类，不知道当事人。分三档：

- **已知**：直接对当事人做义务。
- **候选集**：对每个候选算义务，选择能覆盖最多候选、或最坏情况仍能防的方案。
- **完全未知**：先估计“当前计数最接近阈值的角色”，同时把信息调查当作降低候选集的动作。

第一版先用已知当事人做诊断，确认调度器有效，再接候选集。

## 五、搜索与调度怎么结合

不要一上来做完整跨日信息集树。分三层：

1. **确定性调度器**：已知世界、已知当事人，按截止日分配 `p-1`。先证明能防住大小姐自杀。
2. **信念调度器**：当事人和黑牌用粒子采样，对多个世界求稳健调度。
3. **有界搜索**：只对关键日、关键角色做小树搜索；其余用调度器给的义务分数做启发。

真正完整的两日／三日信息集树放在最后，作为验证工具，不作为第一版在线策略。

## 六、大小姐案例的具体验证

BTX01 第 5 天自杀，当事人大小姐，基础上限 **1**：

- 任何不安 >= 1 都会触发。
- 剧作家可以用暗牌和“传谣”能力持续加不安。
- 红方一天只能放一张 `p-1`，抵消不了每天的总增量。
- 开眼红方也重复输掉这条事故。

结论：大小姐自杀在当前行动经济下接近结构性失败，不能作为“可防住”的验收案例。它适合测试义务提取、阈值读取和调度评分，不适合证明防守能赢。

需要换一个真正可避免的跨日失败条件做验收目标。选择标准：

- 开眼红方能避免，普通红方不能。
- 失败来自可提前处理的计数、位置或保护目标。
- 不是每天都被剧作家强制加压力、红方资源必然不够的结构性失败。

## 七、指标

- 每条义务是否在截止日前满足。
- `lead_days`：提前了几天开始防守。
- `reserved_cards`：为义务保留的牌数。
- `prevented_incidents`：实际避免的事故数。
- 整局胜率和终猜正确数。
- 反事实检查：回放里如果当时多出一张 `p-1`，事故是否不会发生。

## 八、实施顺序

1. 从规则和场景提取 `IncidentObligation`，先支持 BTX 的计数阈值事故。
2. 写已知当事人的确定性调度器，接入一次诊断动作策略。
3. 用大小姐案例验证能防住。
4. 扩展到其他剧本的跨日失败条件，整理同类义务。
5. 接粒子候选当事人，做稳健调度。
6. 最后再考虑有界跨日搜索。

## 九、和可组合 AI 的关系

- 信息策略负责给出：当事人候选、当前计数、未来事故列表、黑方出牌历史。
- 行动策略负责：根据义务做跨日资源调度，再和当天的联合搜索分数结合。
- 这样“身份信念”和“跨日防守”能分开评估，不会混在一起。

## 十、已落地的插拔模块

`tragedy_sim/defense.py` 提供第一版模块接口：

- `DefenseObligation`：结构化义务，包含事故日、当事人、计数、阈值、还差多少、提前天数。
- `DefenseContext`：公开视图、信念快照、剧本、horizon。
- `IncidentModel`：把一个剧本事故转成义务的协议。
- `CounterThresholdModel`：内置“计数到角色上限就触发”的模型，先用于自杀。
- `IncidentModelRegistry`：事故类型到模型的注册表。
- `ScheduledIncidentProvider`：从剧本未来事故提取义务。
- `CounterThresholdScheduler`：按截止日检查候选三牌是否覆盖义务。
- `DefenseModule`：provider 加 scheduler 的组合入口。

扩展方式：

- 新事故类型：实现 `IncidentModel.extract`，调用 `registry.register(kind, model)`。
- 新调度方式：实现自己的 scheduler，或替换 `DefenseModule` 里的 scheduler。
- 新信息来源：替换 provider，从粒子快照、公开日志或自定义候选集提取义务。
- 默认注册表只放 `suicide`；其他类型先不猜，避免把不适用的事故硬套成计数义务。

当前粒子代理里的临时事故守卫仍然保留，尚未切到新模块。下一步先把调度器接进行动评分，再删旧守卫。

### 保护目标模型

同一模块新增 `ProtectTargetProvider`：

- 关键人物、亲友、时间旅行者是需要保护的目标。
- 杀手、连续杀人犯是威胁。
- 当保护目标和威胁同区域，生成“移动目标”义务。
- 当保护目标成为黑方暗牌目标，或已有密谋，生成“禁止密谋”义务。
- `DefenseModule` 可以同时组合多个 provider。

BTX02 测试：

- 第 1 天用 `fi` 禁止女学生密谋，女学生仍然在后续死亡。
- 回放显示第 4 天由“杀手：使女学生死亡”触发，女学生已有密谋，`fi` 只阻止新增，不消除已有密谋。
- 当天红方没有移动牌，无法把女学生移出杀手能力区域。
- 说明这条防守需要**资源感知的跨日计划**：提前保留移动牌，或更早阻止女学生积累密谋。单纯当天 `fi` 不够。
- 同时补了“连续杀人犯独处目标”义务：独处时移动目标。

当前保护义务只验证了提取和打分，不构成已验证的防守策略。

补充对照：BTX02 seed 0，`oracle_cards` 知道当天黑牌，0 个轮回失败获胜。回放显示：

- 第 1 天把女学生移出学校。
- 女学生离开后，连续杀人犯男学生和杀手大小姐独处，男学生杀死大小姐。
- 杀手被清除后，女学生不再受到杀手能力威胁。
- 第 4 天继续移动女学生避开剩余威胁。

这说明 BTX02 的女学生死亡是**可避免的**，关键是：

1. 识别女学生是 key，杀手/连续杀人犯是威胁。
2. 在威胁同区域时优先移动女学生。
3. 移动可能同时让连续杀人犯处理掉杀手，属于可用的战术结果。

普通粒子红方在同种子没有移动牌或没有选择移动，所以失败。下一步的重点变成“什么时候保留/使用移动牌”，而不是继续加 `fi`。

## 十一、风险

- 黑方会针对调度：知道红方保留 `p-1` 后换目标。
- 多个义务争抢有限牌，调度可能过保守。
- 未知当事人导致覆盖成本爆炸。
- 事故条件不只计数，还有移动、封锁、事件嵌套；第一版只做计数型。
- 长期调度若压过当天生存，可能为了远事故输掉眼前。
