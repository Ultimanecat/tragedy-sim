# 完整身份支持与终猜审计（2026-10-13）

## 默认切换前发现的问题

1. 少角色库将每个剧情的一次随机事件占位分配送入 validator。相同人随机分配到两个非连续杀人事件时，整个剧情的全部身份分配被丢弃；库仍可能标为完整枚举。
2. 模仿者在旧枚举／MAP 中作为普通角色分配槽位。实际身份是复制另一名角色、额外存在，不消耗剧情槽位。合法 FS 亲友复制剧本、所有身份已知时，旧 MAP 返回 None；旧库需要构造恢复才能找到该世界。
3. MAP 的贪心事件占位会占用未来已知当事人，输出的角色假说可能附带非法事件安排。
4. `PublicEvidence` 曾把收到的私密初始身份和公开当前身份合并而不保留来源；矩阵采样重建 known_roles 时跳过临时工，遗漏已收到的初始身份答案。病毒公开杀人狂身份允许初始平民替代，私密初始杀人狂答案应排除这一替代。
5. 完整库后续更新只过滤传入 witness，直接传入 PublicEvidence 的新身份知识可能没有生效。

这些是实现支持集和输入传递问题。矩阵仍保留完整假说、剧情数量变体与原始 witness，当前未发现二维边际表示带来的致命缺陷。

## 修复边界

- `belief_role_solver` 对 FS／BTX 复用 `evidence_role_domains`、剧情数量变体和合法事件占位。小库完全枚举普通槽位，再叠加局外人／模仿者额外身份；不消耗 RNG。
- MAP 对每个矩阵变体构造硬／软条件的实现方式，缓存同剧情的等价前缀，再按字典序完成其余身份。完整 matcher、打印规则 validator 和共用后验目标继续检查。
- 额外亲友身份的性别占用传入完成器，不能只检查普通槽位。
- `PublicEvidence.known_initial_roles` 单独保留收到的私密答案、规范化临时工替身。公共身份保留原动态解释，私密身份按初始 cast 精确比较；矩阵域、持续库和后验目标使用相同知识条件。
- 初始先验计数先清除全部观测字段，新增私密身份不能重定义初始分母。先验版本、软 witness 系数、行动估值和 horizon 不变。
- 不支持矩阵的新规则集继续旧枚举／MAP，未扩展公平 AI 模块白名单。真实剧本仅用于测试与对弈后的开发审计。

## 测试与计数解释

新增独立排列＋printed validator 参考，不使用矩阵域／数量 DP。六种 FS／BTX × 模仿者／局外人／两者组合的初始计数完全一致；在硬身份析取与软身份证据下，MAP 最优权重／字典序代表与独立枚举一致。另覆盖已知模仿者无需恢复、非法随机事件占位、未来当事人、私密临时工、病毒公开／私密杀人狂区别和持续库的新知识。

78 项相关专项通过。源码复查又修正旧生成器的临时变量覆盖私密答案字典，增加多条身份观察的反例后，最终全量 737 项通过（164.979 秒）。前端未改；新对弈继续验证。

`ExactRoleMapResult.compatible_count` 记录矩阵传播后数量／域空间的分配数。未完全投影的联合硬条件可继续由 matcher 排除，因此该数是支持外界；它不用于 always／never，也不等于后验概率或终猜成功率。`ranked` 是条件实现得到的 MAP 代表集，最大值通过独立枚举测试；它不保证输出真实全空间的前 K 个分配。

FS／BTX 两个角色额外身份属于同一身份维度内的相关性，已经保留；身份／当事人／暗牌之间的更完整关联仍属于后续任务。
