# 共享联合出牌空间：首阶段实现

## 已实现

`tragedy_sim/joint_action_space.py` 的 `JointActionSpace` 只接收授权团队视图及当前席位合法 offers，不接收真实 Game／剧本身份。支持标准 FS／BTX 的三张联合牌和一／两张已提交的固定前缀。

- 各席位手牌独立，目标互异，限次牌按真实剩余手牌保留。
- 新防守计划禁止密谋总共至多一张；已提交两张时保持前缀，禁止再补 FI，并继续生成合法剩余计划。
- 零不安且当前行动无可能增加来源时删除 −1；无可能有效移动时删除禁止移动；移动按全部公开合法黑牌的最终合成方向判断。
- 非有效区域牌从实质动作域移除，同时保留普通无效区域填充代表，允许只防守一两张、其余不消耗限次资源。无普通填充可用时保留不同限次资源的填充。
- `DefenseRequirement` 支持 OR-of-AND 的必要牌／目标约束、唯一席位传播、已提交满足及冲突。必要性由调用者证明，组件不会把有限样本总失败当成硬事实。
- `ranked_bundles` 扫描全部声明空间，再按排序取有限精确评价名单；支持联合多维排序，三张单独低分的组合可以整体优先。
- 不支持的布局／牌／区域复写／权限形状明确报 `UnsupportedJointSpace`，开眼入口记录回退原因。

数值不变不自动意味着规则效果不变。BTX“恶性病毒”在任意计数变更检查全部角色，−1 在 0 钳制也可触发其它角色转身份。因此当前 BTX 存活角色不安达到 3 时，先回退完整旧引擎路径；后续用明确剧情／当前身份不变量或精确轻量规则处理该情况。此保护未按剧本编号判断，不把可能病毒写成确定剧情。

## 开眼与 CLI 接入

两种开眼构造器有可选 `candidate_policy="joint_enumeration"`，默认 `legacy`。明牌开眼只在此明确作弊模式中向空间提供今日真实明牌，暗牌开眼始终传原授权暗牌视图。公平粒子 AI 尚未迁移，黑方内部回应、房间默认和前端没有改变。

```powershell
python -X utf8 -m benchmarks.ai_self_play --scenario official-fs-01-first-script --games 1 --strategy fixed --protagonists oracle_cards --nodes 16 --protagonist-nodes 16 --oracle-candidate-policy joint_enumeration --progress
python -X utf8 -m benchmarks.ai_joint_space_validation --output references/joint-space-new.json
```

Trace 区分 `enumerated_bundles`、候选数、`evaluated_bundles` 和回退原因。节点预算仍约束昂贵引擎评价，不能把扫描 2 万个组合说成精确模拟 2 万个组合。当前默认入围排序仍为旧单牌排序之和，联合威胁排序和反例搜索留在下一阶段；未宣称这版更强。

## 已暴露的下一瓶颈

同一个 FS01 第 2 轮第 3 天失败根做了 12 个固定节点诊断：两开眼模式×旧／新×4／16／48 节点。新明牌空间扫描 15874 组、新暗牌 22680 组，最终计划的三条实际黑方路线在决策完成后查询。

| 模式／预算 | 旧所选实际存活路线 | 新所选实际存活路线 |
| --- | ---: | ---: |
| 明牌／4 | 3/3 | 1/3 |
| 明牌／16、48 | 3/3 | 3/3 |
| 暗牌／4 | 1/3 | 1/3 |
| 暗牌／16 | 1/3 | 3/3 |
| 暗牌／48 | 3/3 | 3/3 |

报告 `joint-space-oracle-common-root-ordering-final.json` 在上述忽略目录，绑定最终源指纹和输入 SHA；最终突变保护／完整批次修复后，12 个固定工作量决策和实际路线结果与之前诊断逐一相同。不是正式对弈胜率，角色／暗牌路线仍有限。

最重要的反例是新明牌 4 节点退化：单牌排序之和偏好女学生禁止移动、区域禁止密谋，前三张配合仍会让关键人物停在医院被杀。完整空间里存在正确防守，低预算只验证了单牌排序靠前的四组。扫描全域只解决生成层；下一阶段必须用联合位置／计数／能力威胁排序与反例筛选，不能直接切换默认或宣称棋力提升。

此外修复了旧开眼评价的共同批次边界：首候选至少完成一整组世界，超时只能在此后中止，不反复丢弃首组部分行；某个世界中计划不合法时，不能把其它世界的部分成功算成全体存活。限时原子首批可能超过软预算，明确接受并记录耗时。这项正确性修复适用于两种提议策略，固定工作量／合法共同世界下的评价保持一致。
