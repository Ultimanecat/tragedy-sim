# FS日末基准的状态键与缓存（T0.2a）

本页记录 [T0.1精确基准](exact-day-baseline.md)的可选`cached`后端；默认仍为完整`reference`后端，生产AI不变。核心算法、长期信息集约束及论文读 [设计稿](certified-day-game-design.md)。T0.2已有规则键、精确值缓存及手牌顺序压缩，局部牌效程序和观察分支缓存仍待完成。

## 实现与证明范围

- `day_game/keys.py`：独立的`RuleStateKey`和`InformationKey`，不使用删去事件的`Game.state_key()`替代私有规则键。
- `kernel.py`：每条边仍由正式阶段解析器验证、授权和执行。完整拷贝规则字段、公开事件、命令历史、知识和原观察检查点；只丢弃不被FS规则读取的`decisions`、`_resolution_traces`和`_activation_history`三类历史诊断。新边继续产生诊断，不生成可导出完整replay的对象。
- `cached.py`：有容量上限的LRU转置表，只保存已证明的精确0/1及对应首行动。节点／时间／深度限制产生的未知值不入表。原局、缓存中的行动及返回的行动相互隔离。
- `PureDaySolver(backend="cached")`共用该内核和能力树缓存。完整红牌／黑牌域、原来的0/1界剪枝与未知区间保持不变；`reference`继续保留独立完整transition路径。

规则键保留引擎所有其余字段、完整剧本／初始身份、当前身份、角色全部状态、阶段／日／轮、各席手牌与弃牌、已用能力、护卫、队列／待决选项、强制能力窗口与上下文快照、组件和额外字段。集合按集合编码；字典保留插入顺序；列表／元组、可变字典／不可变映射及bool／int分别编码。

版本`fs-rule-v2-hand-multisets`只将每席手牌规范化为有重复计数的多重集，保留所有者与实体牌。FS规则按牌ID做成员检查／移除／追加，合法选项与视图按固定牌组顺序输出；手牌内部回手顺序不改变规则或授权观察。实际Game和观察事件仍完整保留，不重排它们。

**弃牌顺序继续保留。** 班长的回收能力按弃牌列表生成数字选项；相同编号在不同顺序下会回收不同的牌。未实现语义化选项映射前，不能按相同资源集合合并这两个节点。新增测试实际执行同一编号和剧作家确认，验证回收结果不同。

排除项只限上述私有诊断、命令／检查点历史及`State.events`。事件历史在信息键中保留；已知完整剧本的当日0/1完全min/max不依赖看见事件的先后过程。公开／私密已知答案字段仍保守地放入规则键，避免现有规则对知识字段的读取被遗漏。

信息键包含指定观察者的授权当前视图（含完整公开事件）、按可见性过滤的命令历史、该观察者原有的检查点与可见命令记录。红方不读取真实黑牌面或其他席位的私密检查点。已揭牌事件、私密答案等观察差异仍保留不同信息键。

**跨观察历史共享的只有“已知剧本＋day-survival-v1＋完整min/max”的精确数值。** 当前不合并或缓存可供玩家执行的观察分支，不使用信念、固定续演政策、随机种子或未来评价器。`InformationKey`还未成为公平规划器输入，也未实现跨日私密答案历史重建；这些属于T0.4／T1之后的信息集验收。

键与数值仅在当前进程使用，规则定义身份及效用作用域入键；不序列化复用，不跨规则版本读旧缓存。新规则若开始读取此前只写的诊断／事件字段，需重新审计排除表与版本。不能仅因当前测试通过，就将本键移植到其他规则集。

## 回退与验证

仅接受内置FS `Game`及原规则定义。未知对象类型、额外组件、自定义映射和无法编码的循环结构均关闭该节点缓存，转移回退完整引擎；支持编码的新普通字段会进入键。其他规则集及自定义引擎不能复用FS认证。

完整回归944项通过（281.505秒），其中日末基准／缓存专项37项。覆盖：720套黑牌提交逐一对照；完整能力树与独立穷举裁判对照；状态／事件／知识／合法选项相同；限次牌所有者、初始与当前身份、强制快照、队列、额外状态和容器类型不误合并；不同观察历史保持区分；隐藏黑牌及其他席位检查点不进入红方信息键；失败原子性、未知值不缓存、容量淘汰、源码冻结及CLI后端选择。

```powershell
python -X utf8 -m unittest tests.test_day_game tests.test_day_game_cache tests.test_ai_exact_day -v
python -X utf8 -m benchmarks.ai_exact_day --backend cached --nodes 20000 --time-ms 10000 --output references/exact-day-cached.json
```

报告新增后端与容量配置、缓存命中／缺失／存入／淘汰／回退、当前条目数、紧凑与完整clone次数。缓存省下的是重复展开；命中可用更少节点得到同一精确值，节点预算不再等价于相同收益单元数，比较需同时报域覆盖及墙钟成本。

## 固定工作量实验

FS01历史seed2、第2轮第2天，使用已知的合法候选`c禁止移动→女学生、a禁止密谋→职员、b纵移→巫女`。按`CompleteCardSpace.black_bundles()`顺序取前48套黑牌，对每套完整求日末min/max，不设节点／时间截止；两种后端在同一空闲进程内依次运行，原局不变，逐单元断言精确值相同。

手牌规范化源码`63903ed6c8fa42a60fc5c199ba25e13117a0d5e59e4659f5df2089d1b3b9ce9b`下结果：

| 后端 | 完整收益单元 | 能力节点 | transition | 用时 | 缓存命中 |
| --- | ---: | ---: | ---: | ---: | ---: |
| reference | 48 | 3979 | 4795 | 21.014秒 | 0 |
| cached | 48 | 896 | 1151 | 2.280秒 | 123 |

这一固定工作量约提速9.2倍，48列均精确存活；缓存无回退／淘汰。规范化前缓存版同工作量为6.472秒。绝对缓存命中数下降来自更早复用子树、总请求减少，不能仅用命中次数比较收益。该实验只检验此根前48列的数值等价与实现成本；未解完该根全部504列和368640红牌域，不能报告整根有保证存活策略、整体算法最优或生产棋力提升。

完整根的60秒压力测试仍返回[0,1]。另一个候选`c纵移→女学生、a不安−1→职员、b纵移→刑警`在第78套黑牌`fg女学生、i1职员、d医生`被完整引擎与缓存版共同证伪：职员已有密谋2，行动牌加1，医生斜移到都市后发动主谋再加1，日末杀手以密谋4杀死主人公。女学生安全不等于主人公安全；该反例保存在自动测试，不能把候选被证伪解释为整个根无解。

原始根来自忽略目录中的`fair-residual-production-10seeds.json`，选择器与warmstart见T0.1文档；新clone使用专项测试的控制局面。本机复测脚本为`references/ai-calibration/2026-10-17/profile_exact_day_cache.py`，规范化前／后的逐列报告为同目录`cache-fixed48-final.json`／`cache-multisets-fixed48.json`；60秒压力记录为`cache-multisets-root-60s.json`和`cache-multisets-defense-certificate.json`（后者未闭合，无证书）。完整回归输出为`references/exact-day-hand-normalization-regression-20261017.txt`；这些原始资料保持Git忽略。
