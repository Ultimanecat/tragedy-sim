# FS日末基准的状态键与缓存（T0.2a）

本页记录 [T0.1精确基准](exact-day-baseline.md)的可选`cached`后端；默认仍为完整`reference`后端，生产AI不变。核心算法、长期信息集约束及论文读 [设计稿](certified-day-game-design.md)。T0.2的局部牌效程序与状态压缩仍待完成。

## 实现与证明范围

- `day_game/keys.py`：独立的`RuleStateKey`和`InformationKey`，不使用删去事件的`Game.state_key()`替代私有规则键。
- `kernel.py`：每条边仍由正式阶段解析器验证、授权和执行。完整拷贝规则字段、公开事件、命令历史、知识和原观察检查点；只丢弃不被FS规则读取的`decisions`、`_resolution_traces`和`_activation_history`三类历史诊断。新边继续产生诊断，不生成可导出完整replay的对象。
- `cached.py`：有容量上限的LRU转置表，只保存已证明的精确0/1及对应首行动。节点／时间／深度限制产生的未知值不入表。原局、缓存中的行动及返回的行动相互隔离。
- `PureDaySolver(backend="cached")`共用该内核和能力树缓存。完整红牌／黑牌域、原来的0/1界剪枝与未知区间保持不变；`reference`继续保留独立完整transition路径。

规则键保留引擎所有其余字段、完整剧本／初始身份、当前身份、角色全部状态、阶段／日／轮、各席手牌与弃牌、已用能力、护卫、队列／待决选项、强制能力窗口与上下文快照、组件和额外字段。集合按集合编码；字典保留插入顺序；列表／元组、可变字典／不可变映射及bool／int分别编码。手牌顺序也暂时保留，便于第一步保守核对。

排除项只限上述私有诊断、命令／检查点历史及`State.events`。事件历史在信息键中保留；已知完整剧本的当日0/1完全min/max不依赖看见事件的先后过程。公开／私密已知答案字段仍保守地放入规则键，避免现有规则对知识字段的读取被遗漏。

信息键包含指定观察者的授权当前视图（含完整公开事件）、按可见性过滤的命令历史、该观察者原有的检查点与可见命令记录。红方不读取真实黑牌面或其他席位的私密检查点。已揭牌事件、私密答案等观察差异仍保留不同信息键。

**跨观察历史共享的只有“已知剧本＋day-survival-v1＋完整min/max”的精确数值。** 当前不合并或缓存可供玩家执行的观察分支，不使用信念、固定续演政策、随机种子或未来评价器。`InformationKey`还未成为公平规划器输入，也未实现跨日私密答案历史重建；这些属于T0.4／T1之后的信息集验收。

键与数值仅在当前进程使用，规则定义身份及效用作用域入键；不序列化复用，不跨规则版本读旧缓存。新规则若开始读取此前只写的诊断／事件字段，需重新审计排除表与版本。不能仅因当前测试通过，就将本键移植到其他规则集。

## 回退与验证

仅接受内置FS `Game`及原规则定义。未知对象类型、额外组件、自定义映射和无法编码的循环结构均关闭该节点缓存，转移回退完整引擎；支持编码的新普通字段会进入键。其他规则集及自定义引擎不能复用FS认证。

完整回归940项通过（285.070秒），其中日末基准／缓存专项33项。覆盖：720套黑牌提交逐一对照；完整能力树与独立穷举裁判对照；状态／事件／知识／合法选项相同；限次牌所有者、初始与当前身份、强制快照、队列、额外状态和容器类型不误合并；不同观察历史保持区分；隐藏黑牌及其他席位检查点不进入红方信息键；失败原子性、未知值不缓存、容量淘汰、源码冻结及CLI后端选择。

```powershell
python -X utf8 -m unittest tests.test_day_game tests.test_day_game_cache tests.test_ai_exact_day -v
python -X utf8 -m benchmarks.ai_exact_day --backend cached --nodes 20000 --time-ms 10000 --output references/exact-day-cached.json
```

报告新增后端与容量配置、缓存命中／缺失／存入／淘汰／回退、当前条目数、紧凑与完整clone次数。缓存省下的是重复展开；命中可用更少节点得到同一精确值，节点预算不再等价于相同收益单元数，比较需同时报域覆盖及墙钟成本。

## 固定工作量实验

FS01历史seed2、第2轮第2天，使用已知的合法候选`c禁止移动→女学生、a禁止密谋→职员、b纵移→巫女`。按`CompleteCardSpace.black_bundles()`顺序取前48套黑牌，对每套完整求日末min/max，不设节点／时间截止；两种后端在同一空闲进程内依次运行，原局不变，逐单元断言精确值相同。

最终源码`fbb59e0f5bc536d3b96f5494d747af8114fe5e9283a1ea6d5a0e944e61f49d6e`下结果：

| 后端 | 完整收益单元 | 能力节点 | transition | 用时 | 缓存命中 |
| --- | ---: | ---: | ---: | ---: | ---: |
| reference | 48 | 3979 | 4795 | 21.022秒 | 0 |
| cached | 48 | 2666 | 3482 | 6.472秒 | 288 |

这一固定工作量约提速3.2倍，48列均精确存活；缓存无回退／淘汰。该实验只检验此根前48列的数值等价与实现成本；未解完该根全部504列和368640红牌域，不能报告整根有保证存活策略、整体算法最优或生产棋力提升。

原始根来自忽略目录中的`fair-residual-production-10seeds.json`，选择器与warmstart见T0.1文档；新clone使用专项测试的控制局面。本机复测脚本为`references/ai-calibration/2026-10-17/profile_exact_day_cache.py`，完整逐列报告为同目录`cache-fixed48-final.json`；回归输出为`references/exact-day-cache-regression-20261017.txt`。这些原始资料保持Git忽略。
