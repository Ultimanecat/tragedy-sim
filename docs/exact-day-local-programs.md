# FS局部牌效程序与观察边缓存（T0.2）

本页接续 [规则／信息键与数值缓存](exact-day-cache.md)。三个诊断后端为`reference`、`cached`、`compiled`；默认仍为`reference`，生产AI入口不变。完整设计与论文见 [联合行动博弈内核](certified-day-game-design.md)。

## 局部程序

`day_game/local_cards.py`将同一目标上按引擎顺序排列的实体牌编译为不可变数据：移动方向去重后的合成位移、计数正增量／负增量、禁止标志、地点佯攻的原牌名及禁止密谋数量。纯程序用4096条LRU缓存，不包含世界、身份、资源或观察。

执行仍逐目标、逐计数按原顺序进行：

- 先揭牌并冻结幻想的复写目标，再执行移动；相同方向只算一次，三个不同方向合成为零位移时仍保留引擎的移动事件。
- 禁止移动、最终禁入、区域封锁等运行时规则继续查询原引擎。
- 禁止密谋按全部有效原牌／复写牌统一计数；无效化牌排除于效果，原实体牌仍按规则回收／弃置。
- 计数先加后减，每一步都调用原计数触发逻辑；中途跨阈值产生的身份变化不会被最终数值覆盖。
- 地点无效牌的牌名、日志顺序及计数变化中间值全部保留。
- 资源更新只遍历原实体放置，保持席位、限次消耗及弃牌顺序；复写不多消耗一次牌。

`compiled.py`是显式OO执行器，只覆盖移动和计数两个方法，其他流程沿用原Game／阶段解析器。它在已隔离clone上临时使用同一属性字典执行一次命令，统计放在独立slot；返回对象仍为原生`Game`。不修改Game类、全局规则定义或阶段注册，不改变授权／参数验证。侍从随行、强制窗口、能力顺序、拒绝、事件等仍由原引擎控制。

当前支持原生FS牌组的整数牌效。未知效果、未知／不可哈希牌元数据在缓存查找前拒绝编译，该阶段回退原方法；未知规则定义、组件及状态结构沿用原有完整引擎回退。代码、规则和牌组绑定在一次求解中必须冻结，不支持持有旧缓存时热替换规则。

## 两种缓存的区别

| 缓存 | 合并条件 | 保存内容／用途 |
| --- | --- | --- |
| 精确日末数值 | `RuleStateKey`相同；仅已知剧本、当日0/1完整min/max | 只共享已证明数值和首行动，允许不同观察历史共享此特定效用。 |
| 转移／观察边 | 完整执行图与完整命令相同，保留原始资源顺序、事件／命令／检查点历史和可变对象别名 | 隔离的真实后继与按观察者分离的前后观察；不同历史的边不合并。 |

`day_game/edges.py`的执行图不使用手牌多重集压缩，区分列表／字典／不可变映射等类型，并以遍历编号记录共享引用和环，避免相同值但别名不同的输入被混用。私有历史诊断仍排除，当前FS规则不读取这些输出。整个缓存仅限当前进程、冻结规则绑定的内置FS引擎。

每条`ObservationBranch`保存指定观察者的`InformationKey`、不可变`InformationState`前后视图、事件差量和历史替换标记。通过`before_observation.to_dict()`／`after_observation.to_dict()`取得隔离的授权视图，供后续witness更新使用；修改返回字典不影响缓存。默认记录`team`与`m`，独立使用可显式配置其他合法观察者；未配置的观察者不能误取团队观察。

命中时返回隔离的原生Game，调用者修改结果不会污染其他分支。若新效果产生无法编码的状态，则不缓存该边。缓存有容量上限，未知输入回退、失效命中、淘汰及执行统计单独报告。

观察边**默认关闭**：完整历史键、授权快照与隔离拷贝有额外成本。它保留后续复用的接口，不预设当前搜索一定获益。本次不把它接入生产AI，也不把观察边当作已完成的witness／信念更新。更早私密答案历史重建、共同信息集策略、续局估值及跨日／跨轮回仍按T0.4、T1–T3验收。

反事实黑牌替换还会同步剧作家自己的出牌命令与决策记录，避免历史记着旧牌、棋盘却放了新牌。FS暗置阶段的公开事件及红方检查点不含这些牌面，保持不变；完整、部分红牌已提交及截断记录分别测试。完整记录可从剧本重新执行，得到相同棋盘与角色状态；紧凑搜索副本仍不作为完整replay导出对象。

## 验证范围

完整回归968项通过（284.737秒），日末基准／缓存专项61项；输出保存在`references/exact-day-local-program-regression-20261017.txt`。覆盖范围如下：

- 1584个局部组合：全部红／黑牌面（含空）、不同位置、禁行角色／地点及0／2计数，移动和计数的完整状态／事件逐一对照原引擎。
- 720套完整合法黑牌：固定完整红牌，原生完整transition与compiled的揭牌、计数两个阶段逐一对照，包含原始资源顺序、队列、强制窗口、公开事件、决策记录和合法选项。
- 独立穷举日末树：四组联合攻击、纯保障1等控制局面数值一致；0/1界及预算未知语义不变。
- 幻想复写不重复弃牌；侍从多个目的地保留领队的选择与两个观察分支；病毒中间阈值为共享计数原语的受控探针，不扩张FS合法剧本范围。
- 转移缓存分别覆盖：重复命中、原始手牌顺序、不同观察历史、共享引用／环、隔离返回值、配置观察者、容量淘汰、未知字段回退及日末值一致。

以上验证不意味着穷举了全部红牌×黑牌矩阵，不认定真实压力根存在必胜防守，也不认定整局最优。

## 运行

```powershell
python -X utf8 -m unittest tests.test_day_game_local_cards tests.test_day_game_edges tests.test_ai_exact_day -v
python -X utf8 -m benchmarks.ai_exact_day --backend compiled --nodes 20000 --time-ms 10000 --output references/exact-day-compiled.json
python -X utf8 -m benchmarks.ai_exact_day --backend compiled --edge-cache-capacity 32 --nodes 20000 --time-ms 10000 --output references/exact-day-observation-edges.json
```

报告包含后端、规则键／局部程序版本、编译移动／计数／回退次数，以及可选转移边的命中、缺失、存入、淘汰、回退和条目数。数值缓存命中与转移缓存命中分别解读；`continuation_transitions`计逻辑边请求，命中转移缓存后不代表实际重新执行了一次规则。

固定收益单元的最终结果与完整回归见交接说明；本机完整报告留在Git忽略目录。当前下一阶段为T0.3：按需收益矩阵、混合策略与全域最优回应。需保留直接全矩阵／穷举裁判和未闭合上下界，不以有限安全样本代替全域证明。
