# FS / BTX / OF 完整本地对局

## 规则依据与范围

模组内容优先逐项参照用户提供的 [FS 速查表](../resources/rulebooks/0b2d84f17c995d604bf04e818f20af880a5e5a4d388d87450e5969933f33a90b.png)
、[BTX 速查表](../resources/rulebooks/52184bc7f3f57b2166130ecfe1d3579412161208d72faff5f1164fab99a4bf64.png)
和 [OF 速查表](../resources/rulebooks/3fa84bd5c4510724dee88df812473d947da2b1b2e27a9e67ccfa04662756bf76.png)。
角色位置、禁行区域和补充能力文字由 `resources/data.xml` 定位中文牌面。
例如 [医生](../resources/749b822e09179979f15c78506ef95f35b25d45c2c3181414075bbd9d53da8f04.png)
确认剧作家也可使用其第一项友好能力，以及解除禁行持续整轮；
[军人](../resources/e83a5df6cb5b39fd242cdb8f6a27d6555cc41e5d60d7acf685d09708929b59a7.png)
明确其主人公死亡保护持续整轮。
强制与可选能力的同时点顺序参照用户提供的
[惨剧 RoopeR Wiki「FAQ / 系统全体」](https://w.atwiki.jp/rooper/pages/21.html)。

通用流程按本项目当前的本地规则记录实现：包括每日时序、能力声明与拒绝、
当事人判定、对外信息、轮回结束和最终猜测。每个时点的处理顺序是：
先在同一棋盘快照上统一检查并触发全部强制能力；完成后，再由对应玩家决定是否发动可选能力，并按任意顺序结算。
强制能力的来源随后死亡，不会撤销已经触发的效果。
不以其他版本的细节覆盖用户提供的牌面与当前规则约定。

当前支持速查表上全部 FS / BTX / OF 的规则 X/Y、身份和事件，以及各表允许的登场角色。
不支持额外剧本脚本、其余模组、延迟登场、AI 和联机。JSON 中不支持的字段会报错。

桌面热座界面用 `python -m tragedy_sim --gui` 启动。它与 CLI 共用同一个 `Game.dispatch` 状态机；
没有单独实现或复制规则。公共棋盘只调用 `view("spectator")`，主人公只能看自己的手牌，剧作家秘密只在其解锁后出现。
控制权改变、Esc、窗口失焦、最小化和读档都会清除私密操作区并让旧 UI 回调失效。
这是一层防误看的交接帘，不是进程安全边界；同桌玩家仍须避开私密屏幕和含秘密的存档。

## 阶段与选择

```text
日初 → 剧作家三张暗牌 → 领队起主人公各一张
     → 揭示、移动 → 行动能力窗口 → 其余行动结算
     → 剧作家能力 → 领队友好能力 → 事件
     → 换领队 → 日末强制效果 → 日末可选能力
     → 下一天 / 轮回结束判定

轮回结束：成功 → 主人公胜
          失败 → 还有轮回：轮回间讨论 → 重置 → 日初
                轮回耗尽：FS 剧作家胜 / BTX、OF 最终猜测
```

OF 的“时空扭曲”会把下一日改成剧作家四张、主人公两张，并跳过当日领队；界面会显示当天实际牌数与出牌顺序。

`next` 只推进流程，不能代打牌、跳过必选目标、能力确认或最终猜测。
每个时点总是先完成强制能力批次，再开放可选能力窗口。可选能力通过 `options` / `choose` 决定是否发动、合法目标和先后顺序。
需要人类选目标时界面才会暂停，所有目标收集完成后再结算该批效果。
友好能力由领队声明具体来源与目标，再由剧作家确认效果。即便不能拒绝也使用同一个确认阶段，
避免通过“有没有弹出确认”直接透露角色身份。没有任何能力时仍保留统一的阶段窗口。

效果队列可以暂停在事件的第一/第二个目标选择之间，或情报商的规则公开选择处。
每条 `dispatch` 原子执行：非法操作不会消耗牌、次数或损坏之前完成的状态。

## 关键实现约定

| 规则点 | 实现 |
| --- | --- |
| BTX 身份配额 | 改变未来：邪教徒 1、时间旅行者 1；潜伏的杀人狂：亲友 1、杀人狂 1 |
| FS 最黑暗的剧本 | 传谣人 1、亲友 1、另可加入暴徒 0–2 |
| 身份数量 | 所选规则的配额相加，再按传谣人 1 / 亲友 2 的上限截断 |
| 邪教徒 | 移动之后按实际区域选择是否忽略禁止密谋；所有已揭示的牌保持公开可见 |
| 时间旅行者 | 不死，强制忽略禁止友好；末日友好 ≤2 的失败能力仍由剧作家选择发动 |
| 妄想扩大病毒 | 平民不安达到 3 时立即变杀人狂，降回 2 也不恢复；重置才恢复初始身份 |
| 因子 | 获得能力而非身份；都市密谋 ≥2 时死亡会导致失败，但不因此成为杀手可指定的“关键人物” |
| 护卫 / 军人 | 护卫消耗一枚替代一次角色死亡；军人的保护阻止主人公死亡，不阻止其他失败条件 |
| 死亡 | 尸体留在原地，保留计数物；普通能力/出牌不能指定尸体，明确指定尸体的能力除外 |
| 死亡顺序 | 医院事故按同一快照同时处理；多个同时点的强制效果统一触发，两名杀人狂单独同处时互相触发并双双死亡 |
| 亲友 | 中途失败也必须结算其死亡公开；身份曾公开，往后轮回开始加 1 友好 |
| 因果线 | 记录上轮结束时有友好的角色，包含尸体；下一轮重置后给这些角色加 2 不安 |
| 医生 | 若身份允许无视友好，剧作家可用第一项能力；与领队共用每日次数，秘密使用不会直接暴露在公共次数清单中 |
| 友好次数 | 不消耗友好，被拒绝也使用次数；每轮一次的公开使用记录在后续日期仍可查 |
| 最终猜测 | 还原棋盘与剧本初始身份，历史知识保留；逐个猜全部角色，答错立即结束 |

OF 另有以下跨阶段状态：傀儡一旦死亡会在后续轮回保持尸体；两类归来者满足条件时继承全部计数物；
归来者·敌在移动前无效化同区域一张主人公行动牌；捣蛋鬼的指定对象在整局中不能重复。
“重来”的最大日数 -1 是剧本制作约束，JSON 的 `days` 填写已经调整后的实际日数，不在运行时再次扣减。

医生被剧作家秘密使用过能力后，主人公仍可依据公开状态声明；剧作家窗口会限制为“本次无效果”，
既不重复执行，也不通过选项消失泄露秘密使用记录。

## 事件与中断

所有事件先判定：当事人存活且不安达到角色卡临界值。
发生/未发生均进入公开日志；没有合法目标或效果额外条件不满足，不会把“发生”改为“未发生”。
有多个候选目标时必须由剧作家选择，不用隐藏的固定优先级代选。

| 事件 | 结算要点 |
| --- | --- |
| 谋杀 | 同区域另一名存活角色；不能选择当事人自己 |
| 不安扩散 | 第一名角色不安 +2，然后另一名角色密谋 +1；分两步选择 |
| 自杀 | 当事人死亡，仍检查不死和护卫 |
| 医院事故 | 密谋 ≥1 杀死医院所有存活角色；≥2 再使主人公死亡 |
| 远距离杀人 | 任何区域密谋 ≥2 的存活角色，包括当事人也可能成为目标 |
| 失踪 | 合法移动（可原地不动），随后实际所在版图密谋 +1；不能进入禁行区域 |
| 散播 | 第一人友好 -2，不足则减至零；再给不同角色友好 +2 |
| 邪气污染 | BTX：神社密谋 +2 |
| 蝴蝶效应 | BTX：同当事人区域，可选其自身，三种计数物任选一种 +1 |
| 恶意谣言 | OF：当事人区域所有存活角色不安 +2 |
| 毒气扩散 | OF：当事人所在版图与另一个版图各密谋 +1 |
| 曝光 | OF：在当事人区域合计放置或移除 2 友好，可集中或分给两人 |
| 时空扭曲 | OF：下一日剧作家四张、主人公两张，领队不出牌 |
| 自白 | OF：公开当事人的当前身份 |

关键人物死亡或主人公死亡会立即转入轮回结束，丢弃后续效果/选择，避免在已经结束的轮回继续行动。
例如医院同时死亡名单结算后若有关键人物死亡，就不继续宣布后一条主人公死亡，也不再换领队。
但同一时点已经触发的强制死亡先作为一个批次完成，再处理立即失败；因此一名杀人狂在该批次中死亡，不会取消另一个已触发的效果。
但必须检查并公开已死亲友等轮回结束效果。

## 信息边界与阅读

`board` 给出位置、存活、计数物、临界、护卫、保护、公开留置、完整事件日程、事件结果和已声明能力次数。
`inspect` 给出角色初始区域、当前区域、禁行区域、属性、完整能力与被动特性。
`rules` 列出模组全部候选规则、身份、事件与固定牌组；它不是所选剧本的答案。

只有出牌者能在揭示前的 `view` 中看见自己的牌；牌揭示后及公开日志中可见所有牌。
计数物的先加后减会显示中间数值，例如 `2 → 3 → 2`，而非仅显示净变化。
身份/当事人/规则的合法公开写入知识记录，身份信息附带轮回和日期，避免将旧推断当作当前身份。
最终猜测仍保留最后一轮事件记录，完整历史随时可用 `log` 查看。

`view m` 才返回完整秘密；剧作家私密选项不会自动进入公开日志。
公开日志通常只记录影响和结果，不描述秘密来源。OF 中身份能力或关键人物导致轮回失败时，
按速查表的“不确定的败因”只公开轮回结束，不额外暴露主人公死亡原因；公开事件造成的死亡仍正常记录。
这是进程内的视图约定，不是安全沙箱：实际同桌对局请隔离私密屏幕，不能向主人公分享完整存档或输入历史。

## 验证与扩展入口

运行 `python -m unittest discover -v`。
`tests/test_game.py` 与 `tests/test_old_fashion.py` 覆盖全部事件、主线失败条件、身份交互、角色能力、拒绝/限次、
中断、跨轮回知识、FS/BTX/OF 最终胜负、信息过滤、CLI/GUI 和多阶段存档恢复。
还校验 FS/BTX 的全部 114 种与 OF 的全部 105 种规则 X/Y 组合，并以固定随机种子运行合法对局，检查牌守恒、非负计数物、终止与命令重放一致。
这不代表穷举所有可能棋盘；新发现的组合规则应先加入回归测试，再修改引擎。

新增内容的数据入口是 `catalog.py`，剧本结构在 `scenario.py`。
流程在 `Game._advance`，人类选择在 `Game.options`，效果队列在 `Game._drain`，所有死亡统一经过 `Game._kill`。
完整对局外部调用者统一使用 `dispatch`；直接修改内部状态会绕过校验与存档历史。
