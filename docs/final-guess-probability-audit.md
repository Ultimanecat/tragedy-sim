# 终猜联合概率与逐步变化日志

状态：第一版概率组件与可选开发日志已实现。行动规划和正式终猜选择保持原逻辑；黑方信息隐藏评价、终猜策略消融留作后续独立阶段。

## 概率口径

对当前合法证据 E 与完整初始身份猜测 G：

`P(G | E) = 同身份表 G 的全部合法世界后验质量 / 全部合法世界后验质量`

同身份表的不同剧情先汇总，事件／暗牌等未猜测变量在模型中边缘化。沿用当前分维模型时明确其独立近似；后续跨维关联不能被静默忽略。小空间精确求和，大空间使用经过验证的加权计数／重要性估计。当前压缩 MAP 代表、top 候选和支持数量外界不能充当分母，角色边际不能直接相乘。

三个用途分别记录：

- `best_guess_probability`：当前模型下最优整套身份表的概率，附推荐猜测及其是否变化。
- `previous_guess_probability`：把变化前的同一套猜测放入变化后模型评分，区分证据影响与推荐答案切换。
- `true_cast_probability`：真实初始身份表的模型概率，仅供离线真值诊断，或黑方用自己知道的剧本评价其红方信念模型；真实身份只能作为待评分的 G，不能作为红方推断的输入证据。

概率属于当前先验／软 witness 模型，尚非校准的实际胜率。没有相容世界、求解未完成或估计质量不足时记录 unavailable／原因，不能伪装为 0、1 或确定结论。

实现为 `JointGuessProbabilitySolver`：按总身份数量、额外角色身份和相关角色的身份划分不重叠集合，汇总同一身份表的不同剧情质量，精确计数无关角色的合法剩余排列。完整 matcher 与剧本验证保留；额外身份、性别和当前／初始身份解释沿用共同支持规则。单人硬约束已进入各剧情的身份域，无需再次展开对应角色；剩余析取和软评分依赖仍显式展开。

`support_count` 是支持的不同完整身份表数量；`total_mass` 是全部后验质量，均不使用 top MAP 候选或粒子数代替。独立枚举测试覆盖归一化、跨剧情汇总、硬／软和重复证据、角色路线、额外身份、性别、病毒与特殊角色约束。精确结果仍有浮点加法的机器精度误差，ESS／估计误差字段为空。

当前只支持 FS／BTX 分维模型。相容当事人的独立权重在身份归一化中抵消；当事人支持为空时整体不可用。暗牌仅通过编译出的身份 witness 影响本组件。未知因子返回 `unsupported_witness`；工作超限返回 `work_limit`，不输出截断概率。未来跨维相关模型需要新版本的求和口径。

## 触发与记录

接入现有 `BeliefAuditTrail` 与逐命令 replay 审计；复用结构化时间点、证据来源和观察游标，不增加全局 hook。

1. 每次实际新增、移除、再次确认 witness 时，记录更新前／后的概率及 delta；区分实际新观察与公开知识镜像重复编译。
2. 每次行动判定／效果结算后的合法观察，以及 AI 行动决策时，也记录一行；没有新证据时显式标记无证据变化。AI 选择行动本身不能增加身份知识。
3. 同时触发的强制效果先按引擎原子批次记录整体变化，不能构造玩家从未看到的中间状态。单 witness 归因可离线顺序重放或 leave-one-out，注明顺序及交互；各 delta 不保证可加。
4. 轮回自动切换／终局的记录保留原事件的时间点；行动前／后状态和证据时间点分别保存。

每行至少含：命令／决策序号、轮回／天／阶段／结构化 timing、观察者及信息口径、触发行动／事件、witness ID／来源／强弱与增删状态、概率前后值／delta、推荐猜测前后值、旧猜测的新概率、是否精确、估计方法／目标版本、ESS／误差与状态、诊断耗时。黑方公开知识下界、红方团队合法私密知识和离线真值诊断分开标记。

第一版按**完整授权观察的 witness 批次**记录，不拆开强制结算构造中间状态。`changes` 保留全部原始 witness／来源／次数；尚未做单 witness 的 leave-one-out 归因。离线工具在初始状态和每个 replay 命令之后记录；运行时在证据刷新和规划器记录决策样本时记录，无法补造未观察的内部时间点。命令上下文保存 actor／action、执行前位置和新增的授权事件；暗牌内容不从 replay 命令复制到推断上下文。

`guess_all` 额外记录 `submitted_guess_before_reveal`：用提交前模型评分实际提交的身份表。终局公开答案后的值属于另一检查点，不能当作决策时的终猜胜率。FS 没有正式终猜，相关数值仅为身份推断诊断。

提供 JSON 和人类可读文本。例如下列数字仅示意格式，不是已有测试结果：

```text
[第2轮·第3天事件结算后；命令42]
  新增硬证据：自杀当事人为女学生
  最优整套终猜概率：8.0% → 12.0%（+4.0个百分点）
  原推荐猜测在新证据下：10.0%；推荐猜测已改变
  口径：团队合法知识；方法：精确；目标：uniform-printed-casts-v1
```

## 调试隔离与采样误差

- 默认关闭，输出仅进入开发报告／忽略的 `references/`，不进入玩家界面、SSE 或公开 replay；正式 replay 仍只保存原决策与结算。
- 不修改行动候选、生产后验、证据集和生产 RNG；证据／诊断不消耗行动节点预算。额外诊断墙钟单列，限时对弈采用相同采集配置，优先离线重演，避免日志改变限时轨迹。
- 前后比较优先精确计算或使用共同提议及正确密度重加权。需要补样时用独立诊断 RNG，记录批次变化／ESS，区分数值误差与新证据；不能把两个独立小批次的差值直接当信息增益。
- 没有新证据且概率模型不变时，同口径精确值应不变；单次实际观察后最优概率可以升降，不要求每条日志单调增加。

## 黑方应用与验收

先离线定位哪个结算／拒绝／公开失败条件泄露信息，再评估行动的预计变化。黑方在自己的剧本下还需检查真实身份表的概率与排名：红方对错误猜测更自信时，`best_guess_probability` 可能上升，所以不能机械地把它上升全当黑方损失。

信息隐藏用于终局概率／胜负对齐的评估，不能用降低某个日志数值替代获胜目标；行动存活压力、必然公开的信息、沉默和伪装成本分别比较。升级黑方回应模型与奖励单独消融，不混入第一版日志功能。

验收：独立枚举的归一化与同表跨剧情质量；硬排除、软证据、推荐切换、重复观察、无新证据、知识重置／自动轮回、不可解／估计失败；同时批次与多 witness 交互归因；开关不改变固定工作量决策／replay／生产 RNG；日志权限不泄密。逐步概率日志与终猜策略改进分别测试及提交。

## 使用方式与下一步

```powershell
python -X utf8 -m benchmarks.ai_causal_audit references/ai-calibration/2026-10-13/matrix-default-validation-192-cached-seeds03.json --strategy joint --scenario official-btx-06-secret-that-was-kept --guess-probabilities --guess-probability-node-limit 100000 --guess-truth --output references/guess-audit.json --belief-log references/guess-audit.txt
```

`--guess-probabilities` 默认关闭；开启后即使未指定文本文件，JSON 仍包含逐命令记录。离线默认上限为 10000 个身份分支节点，可增大；组件直接使用时默认 100000。`--guess-truth` 需显式开启，只增加 `offline_truth` 查询字段；真实身份不会传入 solver、后验或推荐选择。日／轮回筛选只影响根比较，逐命令概率审计保持完整。

运行时开发入口：`BeliefAuditTrail(probability_solver=JointGuessProbabilitySolver())`，赋给指定 AI 的 `evidence_ledger.audit`。固定工作量已验证行动不变；墙钟任务优先离线重演，因为额外诊断仍占实际响应时间。

后续：压缩多角色析取的等价分支，提高大空间精确覆盖；必要时单独加入有质量诊断的重要性估计。然后比较完整身份表边缘 MAP 与当前潜在世界 MAP 的正式终猜，最后单独接入黑方预计泄露评价。保留不可用状态，不能提高上限后静默吞掉复杂度问题。

## 额外身份分组优化

`extra_identity_partition-v2` 在建立普通角色的依赖集合前，先按局外人／模仿者身份分组。同一个总身份数量下，不同额外身份导致普通角色的印刷槽位不同；提前混合这些域，会把大量无需展开的普通角色也标记为相关。新分组互不重叠，查询索引先匹配额外身份，再匹配相关普通身份；没有削减合法世界、改变先验或软评分。
